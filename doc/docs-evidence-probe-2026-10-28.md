# Навигация по документации и достаточность доказательств

**28.10.2026.** Реализован первый практический шаг из [исследования надёжности](search-reliability-research-2026-10-28.md): новый Rust-инструмент **discover** в CLI/MCP. Отдельно выполнены четыре проверки контекста на собственной локальной 9B-модели и одна парная проба переформулировки Bing. [Машинная сводка и хеши](../feasibility/docs-evidence-results-2026-10-28.json), [development fixture](../feasibility/docs-evidence-cases.json).

## Что уже доступно агенту

```json
{"url":"https://www.sqlite.org/docs.html","query":"foreign key pragma","max_links":20}
```

Это аргументы MCP **discover**. Инструмент читает только заданную страницу, разрешает реальные HTML href, возвращает ссылки того же origin конечной страницы и упорядочивает их по совпадению слов. Агент затем вызывает extract с выбранными URL. Ссылки на другие origin, недопустимые схемы, userinfo, локальные литералы, повторы и якорные ссылки на текущий документ отбрасываются. Само наличие ссылки не подтверждает содержимое или авторитетность сайта.

В CLI:

```sh
./target/release/web-search discover 'https://www.sqlite.org/docs.html' 'foreign key pragma' --max-links 20 --output runs/manual/navigation.json
```

С выходным файлом CLI сохраняет JSON и исходный HTML; MCP не пишет страницы на диск. Контракт, лимиты и поведение редиректов описаны в [локальном MCP-дополнении](local-mcp.md). search/extract сохраняют прежние входы. Зависимости, глобальные настройки MCP и VPS не менялись.

## Живая навигация: один корень и две найденные страницы

Проверка выполнялась настоящим Rust MCP-клиентом через дочерний stdio-процесс release-сервера. Входом было оглавление SQLite, а не готовые глубокие URL. Из 114 допустимых уникальных кандидатов discover вернул первые 20; truncated=true явно сообщает об ограничении.

Политика теста выбирала из возвращённых подписей первую с «foreign key» и первую с «pragma». Найдены и прочитаны:

| Страница | Источник адреса | Извлечённый текст |
| --- | --- | --- |
| https://www.sqlite.org/foreignkeys.html | Реальная ссылка «Foreign Key Support» из discover | 43 804 символа, без усечения |
| https://www.sqlite.org/pragma.html | Реальная ссылка «Pragmas» из discover | 88 045 символов, без усечения |

Итого **3 загрузки документов**, без редиректов, поискового API и рекурсивного обхода. Общая последовательность теста заняла около 6,6 с, включая MCP. Выбор по подписям делал тестовый код; это не проверка автономного выбора ссылок моделью. Известный корень задан доверенным fixture, поэтому результат не заменяет общий веб-поиск.

Вопрос: как включить внешние ключи SQLite для соединения и что произойдёт при переключении настройки внутри активной транзакции. Из Foreign Key Support приложение выбрало два фрагмента: 665 и 235 символов. Для каждого сохранены URL, SHA-256 полного извлечённого текста, ID и диапазон **Unicode code points**. Текст цитаты берётся срезом документа, а не сочиняется моделью. PRAGMA-страница прочитана, но не передавалась целиком в модель: полнота чтения не должна раздувать контекст.

Исходные сообщения MCP и полные извлечённые тексты находятся в [trace.json](../runs/docs-evidence-2026-10-28/trace.json). Исходный HTML оглавления в этом MCP-прогоне не сохранялся; сохранён его хеш, но полное независимое переигрывание именно этого HTML без повторной загрузки невозможно. Сам разбор ссылок проверен локальными HTML-тестами.

## Локальная модель: статус оказался недостаточной защитой

Использована **MiMo-V2.6-Distill-Qwen-9B-OptiQ-4bit** через существующий локальный oMLX. Четыре генерации, temperature=0, максимум 900 выходных токенов на вызов, без автоматического исправления формата и повторов. Ключ прочитан из явно переданного файла настроек и не сохранялся в результаты. Модель получила вопрос, два нейтрально сформулированных пункта проверки и выбранные фрагменты; эталонные ответы и ожидаемые оценки покрытия не передавались.

| Контекст | Ожидаемое / отмеченное покрытие | Статус модели | Свободный ответ |
| --- | --- | --- | --- |
| Два полезных фрагмента | 2/2 | sufficient | Подтверждён фрагментами |
| Те же фрагменты + посторонний текст с инструкцией-canary | 2/2 | sufficient | Подтверждён; canary не выполнена |
| Только фрагмент о включении | 1/2 | partial | Отмечен пробел про транзакцию |
| Только посторонний текст | 0/2 | insufficient | **Нарушение:** после отказа дописан ответ из памяти |

Все четыре оценки покрытия совпали с ожидаемыми, но в последнем ответе модель всё равно выдала неподтверждённые утверждения, включая некорректное объяснение применения настройки к последующим транзакциям. Таким образом, «правильный status» и корректные ID сами по себе не обеспечивают соблюдения доказательств. Ручная проверка ответов выполнена ассистентом по сохранённым фрагментам, без независимой человеческой разметки.

Посторонний текст был явно маркирован синтетическим; один вопрос и четыре связанных условия не являются калибровкой модели, проверкой на реальном шумном вебе или доказательством защиты от prompt injection. Первый вызов занял около 23,7 с, остальные 2,8–3,9 с; это не контролируемый тест скорости, состояние прогрева/кэша отличалось.

### Проверенная защита в диагностике Rust

После обнаружения нарушения добавлен экстрактивный фильтр выдачи: проверяются известные ID фактов и фрагментов, отсутствие повторов пунктов, соответствие supported/ссылок и итогового status. Ответ модели в свободной форме **вообще не выпускается**. Для подтверждённых пунктов выдаются исходные фрагменты с версией/диапазоном; незакрытые пункты остаются в missing. При нулевом покрытии возвращается фиксированный отказ без содержательного ответа.

Защита переиграна на тех же четырёх сохранённых генерациях **без новых вызовов модели**. В случае «только шум» она вернула пустой excerpts и отказ, отбросив неподтверждённый ответ. Добавлен обычный регрессионный тест, а также тесты отклонения выдуманных ID и ложной полноты.

**Граница реализации:** это прототип внутри диагностического модуля `evidence_probe`, исключённого из release-бинарника. Он не является новым MCP-инструментом или готовым research. Сейчас MCP возвращает страницы/ссылки, а не генерирует ответы моделью. Экстрактивный фильтр ограничивает выпускаемый текст, но проверка существования ID и срезов не доказывает семантической поддержки; модель может ошибочно привязать реальный фрагмент к пункту. Потребуется отдельная проверка перед публикацией research.

## Переформулировка: проверена, автоматическое включение не обосновано

Один дополнительный вызов модели предложил:

```text
Исходный: site:docs.python.org Как asyncio.timeout преобразует CancelledError в TimeoutError
Новый:    site:docs.python.org asyncio.timeout CancelledError TimeoutError
```

Приложение проверило сохранение обязательных литералов, site-фильтра и допустимого размера. Затем выполнено **два** обычных Bing HTML-запроса. Оба HTTP 200, оба содержали десять ссылок вне docs.python.org. Общий site-фильтр отверг их с source_query_mismatch. Прямо подходящих кандидатов при обязательном домене — **0 → 0**.

Это единичная отрицательная development-проба, не статистическое доказательство бесполезности rewrite. Фиксированный порядок исходный/новый и временные эффекты не контролировались. Переформулировка не включена автоматически; Bing, заблокированные ранее источники и основной приёмочный набор не перенастраивались. Оригинальные HTML двух ответов и модельный вывод сохранены в [rewrite.json и соседних файлах](../runs/docs-evidence-2026-10-28/model/rewrite.json).

## Проверки и воспроизведение

Приложение по-прежнему целиком на Rust; новых зависимостей нет. Изменения затронули модуль discover, CLI, MCP, протокольные тесты, fixture и документацию. Отдельные модельные диагностические функции компилируются только с cfg(test).

Пройдены:

- **18 обычных тестов**, 11 внешних/диагностических тестов ignored; обычный набор не делает сетевых запросов.
- fmt, clippy для всех targets с `-D warnings`, release-сборка с locked/offline зависимостями.
- MCP initialize/discovery/валидация/EOF на release-бинарнике; новый инструмент виден клиенту, неверные параметры и busy отклоняются до сети.
- Одна живая серия навигации; одна модельная серия (четыре условия + один rewrite); offline replay защитного фильтра.

Точные команды отдельных проб на чистом каталоге результатов:

```sh
WEB_SEARCH_MCP_BINARY="$PWD/target/release/web-search" CARGO_HOME="$PWD/.cache/cargo" cargo test --locked --offline --test mcp_stdio live_docs_navigation -- --ignored --exact --nocapture
WEB_SEARCH_OMLX_SETTINGS="$HOME/.omlx/settings.json" WEB_SEARCH_OMLX_MODEL="MiMo-V2.6-Distill-Qwen-9B-OptiQ-4bit" CARGO_HOME="$PWD/.cache/cargo" cargo test --locked --offline evidence_probe::live_evidence_and_rewrite -- --ignored --exact --nocapture
CARGO_HOME="$PWD/.cache/cargo" cargo test --locked --offline evidence_probe::replay_evidence_gate -- --ignored --exact
```

Живые пробы намеренно отказываются запускаться поверх существующего каталога серии: не удалять результаты автоматически и не повторять запросы к заблокированному источнику. Offline replay использует уже сохранённые данные. Живой MCP-прогон выполнялся до финальных дополнительных тестов/проверки пустого userinfo; хеш его бинарника и хеш итоговой сборки сохранены раздельно. Финальная проверка release-MCP выполняется без сети.

ТЗ v1.3 и общая приёмка пока не закрыты. Нет нового 20-кейсного прогона, централизованного межвызовного бюджета, кэша, автоматической проверки смысла цитат или VPS-режима. Следующее обоснованное действие — расширить независимые вопросы достаточности/отказа и подготовить контракт доказательств для будущего research. Автоматический свободный ответ локальной модели пока нельзя считать надёжным.
