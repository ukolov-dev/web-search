# Новости Воронежа: живой тест 3 ноября 2026

**Текущий MCP умеет находить местные СМИ и читать их статьи, но ranked_search сам не собрал свежую новостную подборку.** В трёх заранее заданных запросах с датой/периодом конкретных подходящих статей в top10 оказалось0. Встроенный веб-поиск исследователя нашёл5 подходящих страниц на тех же3 запросах, из них3 подтверждены открытым текстом. Это качественное сравнение разных систем, не измерение их полного recall.

Короткая пользовательская фраза «новости Воронежа» заметно лучше находит местные источники. Однако ranked_search вернул9 direct, включая страницу скачивания приложения, и ни одной отдельной датированной новости. Через существующий агентский путь search→discover→extract удалось перейти с найденной главной к двум конкретным статьям. Этот ручной путь не встроен в ranked_search и не исправлен в рамках теста.

## Что и как проверяли

[Протокол](voronezh-news-2026-11-03-protocol.md) сохранён до первого сетевого обращения. Основные запросы:

1. «новости Воронежа сегодня 3 ноября 2026»;
2. «Воронеж перекрытие дорог транспорт ноябрь 2026»;
3. «Воронеж культурные события мероприятия 3 4 ноября 2026».

Для каждого настоящий локальный stdio MCP последовательно вызвал search(Seznam), search(Naver), ranked_search, max_results10. Release SHA256 и параметры версии сохранены в manifests; runtime `request-evidence-v10-admission-literals`, DeepSeek V4.1 Flash1017 через ранее настроенный OpenRouter, локальный Qwen3-Reranker-0.6 B-4bit. Ключи/содержимое настроек не сохранялись. Бинарник и продуктовый код не менялись.

Grade2 — отдельная конкретная статья с наблюдаемой подходящей датой/периодом и связью с городом. Grade1 — фон, недатированная карточка, рубрика/главная или неполная связь;0 — чужая тема/география. Для первого запроса публикации1–3 ноября2026; для второго ограничения, действующие в ноябре; для третьего события3–4 ноября. Давняя публикация о продолжающемся ограничении может быть пригодной. Главная с полезной лентой остаётся grade1 по заранее заданному правилу конкретных статей.

Source-only reviewer оценивал карточки без reference-выдачи и сети; другой участник сделал reference-поиск и чтение. Родитель повторил подсчёт и проверил реальные ответы/свидетельства. Это работа текущей команды, не формальная независимая приёмка.

Ranked_search поднял7 тематических фоновых карточек первого запроса выше посторонних. У остальных двух все результаты irrelevant; при этом MCP status=ok. Все30 ranked URLs уже были в двух простых выдачах того же запроса. Свежих статей ранжирование не добавило.

Source/extraction errors внутри ranked не зарегистрированы. Qwen реально вызван только для первого запроса:4 вызова/25 пар; для двух остальных0 вызовов и0 чтений. По этому опыту нельзя выделить эффект одного reranker.

Reference тоже несовершенен: первый запрос дал9 рубрик/главных, в транспортном встречались завершившиеся октябрьские ограничения и Россошь. Дубли рубрик/варианты www сохранены, не изображены независимыми источниками.

## Короткая фраза: отдельная диагностика

После основных результатов, до нового вызова, в протокол добавлена точная фраза «новости Воронежа». Эта постфактум выбранная проба не заменяет три исходных запроса.

| Ветка | Тематические карточки, включая приложения | Прямые новостные сайты/каналы | Отдельные свежие статьи |
| --- | ---: | ---: | ---: |
| Seznam | 6/10 | 2/10 | 0/10 |
| Naver | 10/10 | 9/10 | 0/10 |
| ranked_search | 10/10 | 9/10 | 0/10 |

Ranked выдал9 direct и1 background. Главные местных СМИ пригодны как навигация: отсутствие явной даты в коротком запросе не делает их автоматически ложными direct. Но **C009, [страница загрузки приложения](https://www.slunecnice.cz/android/sw/novosti-voroneza/), получила нежелательный direct для намерения читать новости**. Проверка приняла рекламное описание приложения из SERP, audit_supported=true, read_attempted=false. Это ошибка типа результата по наблюдаемой карточке; полного оригинала этой страницы не читали, общий semantic FP/precision не установлен. Временную precision по9direct тоже не заявляем.

## Что удалось прочитать через наш MCP

Главная [РИА Воронеж](https://riavrn.ru/) была найдена продуктом в первой серии. Дополнительный discover этой главной, query=Воронеж,max_links30, вернул реальные same-origin ссылки. Из них выбраны и успешно прочитаны extract две статьи; URLs не получены из reference:

- [Новогодняя площадь Ленина](https://riavrn.ru/news/novogodnyaya-ploshad-lenina-v-voronezhe-budet-rabotat-s-21-dekabrya-po-13-yanvarya/): по сообщению издания, площадка будет работать21 декабря–13 января; дата на странице2 ноября19:05.
- [Спасение женщины из пожара](https://riavrn.ru/news/v-voronezhe-kinolog-spas-zhenshinu-iz-goryashego-doma/): издание сообщает о спасении60-летней женщины сотрудником кинологической службы на улице Дорожной; дата3 ноября10:50.

В извлечённых датах этих двух статей **год отдельно не сохранён**; у первой есть связанный сезон с мартом2027. Дополнительный web-open первой подтвердил текст, год публикации отдельным полем не показал; вторая недоступна этому веб-инструменту, хотя product extract успешен. Поэтому две прочитанные датированные статьи не добавлены задним числом в основной fresh2 score и не названы двумя источниками с независимо доказанной полной датой2026. Copyright2026 сам по себе датой публикации не считается.

Предел discover тоже наблюдаем: точный токен Воронеж почти не совпал с формами «Воронеже», «Воронежский». Ссылка на правила использования получила lexical match, нужные статьи оказались на позициях41–42 исходной страницы и попали в30links лишь с сохранённым DOM-порядком среди остальных. Выбор подходящих заголовков сделал агент. Это не автоматическая новостная навигация.

Отдельные extract контрольных URLs из reference не засчитывались retrieval. [Статья об отключении воды](https://voronezhnews.ru/fn_1984380.html) успешно прочитана: публикация02.11.2026, объявленное событие03.11.10:00–14:00. Статья VRNГрад о программе3–4 ноября тоже читается. Горком36 про улицу Куколкина получил fetch_timeout, повторов не было. У программы праздника reference обнаружил расхождение между VRNГрад иМК по адресу/числу мероприятий; официальный план не проверен, эти детали не выдаём как установленные.

## Затраты и воспроизводимость

Первая попытка в песочнице дала DNS/model transport errors. Все9 ошибочных ответов сохранены отдельно `sandbox-denied`; они не оценены как провал качества. Ровно те же запросы затем выполнены с разрешённой сетью. Новая короткая серия начата после проверки отсутствия source/host blocks; перезапуск не использовался для обхода блокировки.

На4 реальных запроса:16 логических обращений к Seznam/Naver (8 простых+8 внутри ranked),7 генеративных,8 внутренних чтений,8 Qwen-вызовов/40 пар. Дополнительно9extractURLs:8 успехов/1timeout, и1discover. Reference:3 поиска/8open (6 читаемых/2cache-miss); ещё2web-open для дат РИА (1 читаемый/1 недоступный). Сетевые отказы/пустые места сохранены. Стоимость OpenRouter в публичном MCP-ответе не опубликована, денежную оценку не выдумываем.

Wall time ranked:36,2 с,3,8 с,7,2 с,53,3 с соответственно. Это разные вопросы и бюджеты, не доказательство ускорения/замедления относительно встроенного поиска. Публичный вывод не раскрывает все generative input/output, rawHTML целевых страниц также не архивировался этим production MCP; здесь сохранён его полный доступный ответ, а не полный внутренний benchmark trace.

## Вывод

Для получения списка местных СМИ короткий запрос и Naver уже полезны. Для готовой новостной подборки со свежими конкретными статьями текущий ranked_search в этом тесте слабее встроенного веб-поиска. Из существующих MCP-инструментов агент может вручную собрать нужный путь; результат2 прочитанных статей относится именно к этому пути.

Следующее обоснованное направление — обнаружение ссылок на публикации из найденных лент и явные публикационные/событийные даты с различением типов страниц. Ещё одна настройка Qwen сама по себе не создаст отсутствующих в пуле статей. Это рекомендация, не реализованная функция.

Запрошенный ограниченный тест завершён. Новостная квалификация, web-wide recall, повтор в другой день, независимая проверка всех фактов, официальный праздничный план, нагрузка и VPS не выполнялись. V10 остаётся экспериментальной: этот тест не отменяет прежний failed quality gate.
