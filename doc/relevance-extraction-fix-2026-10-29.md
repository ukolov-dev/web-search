# Релевантность и извлечение: исправления и новый набор — 29.10.2026

Потери основного текста JCAR/n8n воспроизведены и исправлены в общем Rust extract. Переоценка релевантности снижена консервативным классификатором с проверкой цитаты и обязательных литералов. **Это обмен precision на recall, а не общее улучшение поиска:** на development12 ложные direct снизились с 47 до 6, но распознаны только 16 из 28 полезных карточек; успешных top10 стало 4/12 вместо 5/12. На шести последующих вопросах все три direct оказались релевантными по собственной оценке автора, однако пропущены пять из восьми полезных карточек.

[Машинные результаты и оценки всех кандидатов](../feasibility/relevance-extraction-results-2026-10-29.json). Задача TASK-20261029-201619-001. Оценка собственная, не независимая acceptance. Original20 и frozen формы B17 не изменялись. Полный пилот не принят.

## Изменение классификатора

`conservative-evidence-v2`, локальная MiMo-V2.6-Distill-Qwen-9B-OptiQ-4bit. Изменения затронули [model.rs](../src/model.rs), [policy.rs](../src/policy.rs), CLI/MCP и [контракт](local-mcp.md).

1. Промпт требует подтверждения отношений между всеми аспектами вопроса. Биография, copyright, магазин/курс, общий каталог и одиночное упоминание технологии не становятся direct из-за известного домена. При недостатке данных — background.
2. Для direct модель возвращает одну дословную цитату 16–160 символов из title либо snippet после нормализации whitespace. Rust проверяет реальное наличие цитаты. Цитата подтверждает происхождение текста, но не доказанность всех аспектов вопроса.
3. Дополнительный Rust gate проверяет явно названные технические идентификаторы: CamelCase/snake_case, составные заголовки, аббревиатуры, версии/числа и заданный месяц. Проверяются карточки, не репутация домена и не содержание URL. Для нескольких HTTP-кодов допускается любой из них, кроме сравнительного запроса. Месяцы поддерживают EN/RU названия и числовые ISO/Korean варианты. Это буквальная защита, без универсального понимания синонимов.
4. Неподтверждённый direct понижается до background, evidence убирается, ответ получает partial и grounding_downgrades. Неполный/невалидный JSON сбрасывает метки целиком и оставляет partial RRF. Повторов/ремонта формата в runtime нет.
5. Внутренний JSON — labels с обязательными ключами ID и значениями kind/evidence. Валидатор отклоняет повторные ключи, неизвестные/пропущенные ID и незавершённый ответ. Массив в первой пробе нового промпта повторил ID; проба сохранена как неудачная, не засчитана в итоговый вариант.

Температура 0, thinking=false, tools=none; max_tokens повышен с 1200 до 2400 для цитат. ≤3 классификации/вопрос, ≤24000 символов source context/вызов, ≤8 логических SERP и 180 секунд retrieval/classification сохранены. Модель на loopback задаётся только доверенной startup-конфигурацией. Новых внешних API и model URL/key аргументов MCP нет. Site/DNS/IP/redirect/circuit защиты сохранены.

## Новый development12: парное сравнение

Seznam/Naver: 24 обращения, все HTTP 200, одна Naver parser_changed (d04), без блокировок и повторов. Получены **213 уникальных кандидатов**, из них 28 получили ручную оценку 2. Все 213 карточек оценены по title/snippet/URL в проекции без модельных меток; commit/hashes сохранены.

Старый B17 и новый вариант оценивались на одних и тех же capture/context. Сначала проверен консервативный промпт с цитатой, затем development12 использован для диагностики оставшихся ошибок и проектирования literal gate. Поэтому финальная оценка development12 **in-sample**, не holdout. Raw ответы не переписывались; gate v2 применён к сохранённым keyed-ID ответам без новой генерации.

## Исправление extract: red → green

В исходном свежем HTML текст присутствовал, но Readability выбирал неверный объём: JCAR — длинный references вместо abstract; n8n — начало документа без важных разделов. Дополнительно полный текст JCAR был на другом явно указанном URL; первоначальный выбор abstract скрывал тело и на этой странице.

Общий [extract](../src/main.rs) теперь сначала берёт единичный main/role=main или article. На научной странице с citation_title приоритет имеет article-body/role=doc-body, затем abstract с языковыми вариантами; при отсутствии таких сигналов остаётся Readability. Выбранное поддерево сериализуется один раз, сохраняя div/pre/таблицы и не дублируя вложенные p/li. Убраны scripts, навигация, скрытые элементы и кнопки; title ограничен head. Лимиты HTML/DOM/текста не расширены.

| Страница | До | После | Что проверено |
| --- | --- | --- | --- |
| n8n SSRF | 1797 символов, пропущены настройки/IPv6 | 2165, semantic_main | ENV-настройка, DNS rebinding, fc00::/7 присутствуют |
| JCAR landing | 7567, в основном references | 1776, scholarly_abstract | Английский и корейский abstract; есть содержательное описание earthworks/simulation |
| JCAR fulltext, отдельная загрузка | 1786, только abstract в первой пробе | 9248, scholarly_body | Тело статьи и разделы, включая вводный основной абзац |

Больше символов не равно лучше: для landing стало меньше текста, потому что вместо библиографии возвращён нужный abstract. Страница полной статьи прочитана отдельно один раз. Автоматического следования fulltext metadata нет: доступный URL возвращается в available_fulltext_url и требует явного следующего extract.

Новые поля: extraction_method, content_scope, coverage=not_verified, warnings, available_fulltext_url. abstract_only не выдаётся за статью; truncated=false сообщает только об отсутствии финального обрезания. Полнота относительно PDF, рисунков, формул и всех разделов автоматически не доказана.

Три регрессионных теста используют HTML fixtures реальных страниц: [tests/fixtures/extract](../tests/fixtures/extract/). Первые два упали до исправления; отдельно воспроизведён выбор abstract вместо article-body. Те же assertions проходят после исправления. Проверены также отсутствие повторов вложенных блоков, div/code и title без SVG-иконок. Реальный release MCP extract повторно прочитал n8n и подтвердил ENV/IPv6-маркеры. Дополнительные поля возвращаются через общий CLI/MCP путь.

## Выполнение и ограничения среды

Сохранены все неудачные пробы: первый массивный ответ с duplicate ID, прерванный keyed-ID прогон после восьми случаев, продолжение только четырёх недостающих случаев и отклонённый follow-up baseline. При первом memory rejection oMLX сам выгрузил модель; продолжение выполнялось после этого изменения состояния. Runtime автоматических повторов не делает.

Всего в этой задаче: **40 внешних попыток загрузки** (36 SERP + 3 исходные страницы + 1 MCP n8n), **33 классификационных попытки**, из них 31 ответ модели и 2 prefill/memory HTTP400; 5 metadata-проверок. Source CAPTCHA/блокировок не обнаружено, одна parser_changed сохранена. Локальные oMLX/global memory-настройки, VPS, hooks и конфиги клиентов не менялись. Браузер не запускался, обход блокировок не добавлялся.

Полные raw/evidence: runs/relevance-extract-2026-10-29. Там baseline, failed fixed, fixed-v2, continuation, final-v2, корпуса/projections/grade commits, capture/error logs и снимок фактически исполнявшихся исходников. Одноразовые dated Rust harnesses убраны из основного модуля после сохранения; оставлен общий явно запускаемый ignored capture_relevance_suite с WEB_SEARCH_CASES/OUTPUT/OMLX_SETTINGS и запретом перезаписи каталога. Обычные проверки не обращаются к сети/модели. Подробная история чисел не переписывается.

## Дальнейшая граница

Исправление extraction подтверждено для трёх HTML-структур, не для всего веба. Классификатор стал осторожнее, но ложные direct на development остались, recall снизился и общая успешность retrieval не выросла. Для следующего улучшения нужны свежие вопросы и ограниченная проверка содержимого выбранных страниц, чтобы отличать бедный сниппет от действительно неполного источника. Этот этап не публикует research, factual-answer gate, универсальный rewrite или общий межвызовный бюджет и не заменяет day2/независимую приёмку.
