# Надёжность поиска — 28.10.2026

**Результат:** исправлена передача чужих доменов в ответ на site-запрос. В живом сценарии настоящий агент получил одну официальную страницу Tokio после отбрасывания девяти посторонних ссылок и ответил по её тексту. Добавлен экспериментальный HTML-адаптер Mwmbl, однако пригодная пара поисковых источников всё ещё не подтверждена.

## Исправления общего кода CLI/MCP

- Один `site:domain[/path]` проверяется локально после нормализации URL. Проверяются границы домена и сегментов пути, а не простое вхождение строки.
- Частичное соответствие возвращается как partial с discarded_results и предупреждением. Непустая выдача, полностью нарушившая site, даёт source_query_mismatch и пустой results. Явная пустая выдача — empty.
- Неподдерживаемые сложные выражения site и некорректные ограничения отклоняются до сети. Полный синтаксис описан в [контракте MCP](local-mcp.md).
- У поисковых сбоев появились машинные error_code. Отключение источника зависит от кода, а не от подстроки captcha, которая могла оказаться в самом пользовательском запросе или URL ошибки.
- Распознаётся сохранённая антибот-страница ожидания с HTTP 200. Она не превращается в пустой успешный поиск; новые сетевые запросы к Marginalia не выполнялись.

Изменены общие функции search, вызываемые CLI и MCP. Новые зависимости, модель, кэш и серверный режим не добавлялись.

Для Mwmbl используются только обычные HTML-страницы; Seed Search не включается. По [официальному компоненту frontend](https://github.com/mwmbl/front-end/blob/31eb23207d7b21017208e96345eb53761b82d3fa/src/lib/components/custom/search/SearchResult.svelte) метки Mwmbl, Wikipedia и EUSP различаются. Адаптер сохраняет допустимые Mwmbl/Wikipedia в result_source и отклоняет EUSP/неизвестные метки. Это не утверждение об отсутствии внутренних API у стороннего сервиса; приложение не вызывает его поисковые API и не передаёт ключи.

### Предварительная оценка Mwmbl

Использован неизменённый набор v2 и [прежняя шкала релевантности](search-quality-rubric-v1.md). Прогон сначала остановился на локальной слишком строгой проверке метки Wikipedia; удалённой HTTP-блокировки не было. После проверки исходников исправлена допустимая метка и выполнены только en09/en10, без повторения 18 успешных запросов. В сводке явно сохранены два хеша бинарника и происхождение каждого случая; это диагностическая оценка, а не формальная приёмка одного релиза.

По ручной SERP-разметке этого агента: **2/20**, 33 ссылки, 11 пустых выдач. Прошли en04 (Tokio) и en09 (графемы/кодовые точки). RU-покрытие слабое. en04 был неудачным у Bing в прежнем baseline, поэтому новый источник иногда полезен, но основным или квалифицированным резервом не объявляется. Автоматическое объединение источников не реализовано; их объединённое качество не измерялось.

Полные результаты и оценки: [reliability-mwmbl-evaluation-2026-10-28.json](../feasibility/reliability-mwmbl-evaluation-2026-10-28.json). HTTP 200 и успешный capture не засчитываются как качественный поиск. Ранее заблокированные DDG/Brave/Mojeek повторно не запрашивались.

## Проверка настоящим агентом

Codex CLI 0.164.0 запущен с временным MCP-конфигом, ephemeral/read-only, без встроенного веб-поиска. [Контрольный вопрос](../feasibility/reliability-agent-case.json): роль Tokio, выполнение задач и асинхронные средства. Это интеграционная регрессия, не новый приёмочный набор.

Агент вызвал Bing с site:tokio.rs. Сервер вернул **partial: 9 чужих ссылок отброшены, одна официальная сохранена**. Предупреждение дошло до клиента. Агент вызвал extract для https://tokio.rs/, получил 1721 Unicode code point и подтвердил 3/3 обязательных факта по этому тексту. Ответ содержит проверенный базовый URL источника. Время — **29,25 с**.

Переключение на Mwmbl было разрешено условием теста, но не понадобилось: оставшаяся страница дала достаточные материалы. Поэтому этот прогон подтверждает site-фильтр, сохранение полезного partial и дальнейшее чтение; **автоматический или агентский fallback им не подтверждён**.

События и оценка ответа: [reliability-agent-results-2026-10-28.json](../feasibility/reliability-agent-results-2026-10-28.json). Это внешний агент-клиент; oMLX research не тестировался. Глобальная MCP-конфигурация не менялась.
