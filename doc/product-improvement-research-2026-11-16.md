## Приоритетные эксперименты

1. **Читать нужную секцию до обрезки.** F02 теряет trailers за100000символов. Сначала на сохранённом HTML сравнить нынешний prefix и выбор разделов по заголовкам/anchors+терминам вопроса. Сохранить общий предел текста/времени, идентичность документа и точные Unicode quotes. Нельзя объявить offsets сокращённого текста offsets исходника: нужен явный mapping или честная версия выбранного текста. Критерий: content+trailers получены, без потери no-store и без ложных matches в оглавлении, sidebar, соседнем RFC. Не увеличивать лимиты вслепую.
2. **Замкнуть доказательства каждого вывода.** Для J01 inference должен ссылаться на собственную общую норму и входы вопроса. Частный пример car/bike не доказывает результат7/9. Проверять подмену сущности/числа/версии, отрицания и условий. Контроль: удаление общего правила должно приводить к отказу, его возврат — восстанавливать ответ; хорошая соседняя цитата не спасает плохой claim. Существующего quote-bound prompt недостаточно; сначала измерить проверку нормализованного утверждения на frozen fixtures.
3. **Добор только незакрытых условий.** Использовать уже имеющиеся checks/missing, резервировать последнюю доступную форму/чтение под недостающий факт. Повторять тот же общий запрос не нужно. Для G07 искать общий контракт, для G08 условие panic, для F12 — собственную норму429. Никакого обхода отказов или расширения2forms/4SERP/4reads/4Qwen/6generations/180s. Сравнивать с нынешним planner; не вводить ещё один LLM call вне бюджета.
4. **Два режима оценки.** Offline одинаковые документы изолируют extraction/selection/audit; live новые RU/EN вопросы измеряют полный путь. На каждом условии фиксировать found→extracted→selected→cited→supported; дополнительно полный ответ, unsupported IDs, стоимость/p95 и долю отказов. Включить другие семейства источников, вопросы со свежими фактами, no-evidence, противоречия, site/version и неизменные controls. Заморозить gold/настройки до inference. Gate: нет новых false/unknown, нет потерь прежних supported conditions; средний рост не компенсирует нарушение.

Порядок: эксперимент1→2→3, оценка4 обслуживает каждый. Первыми дешёвыми проверками остаются frozen F02/G07/J01 и пропущенный current-runtime F12 replay. При стабильном улучшении — отдельный новый live набор и независимая приёмка. Модели/embedding/hybrid retrieval сравнивать позже на одинаковом corpus: сейчас нет доказательства, что они исправят потерянный до rerank текст.

Не предлагаются GraphRAG, новая vector DB, массовые параллельные агенты, сторонний scraping/search API или перенос Python-runtime: текущие дефекты этого не требуют. Не создавались дубликаты backlog, не изменялись критерии существующих задач. Публичный браузер и production остаются отдельным scope.
