# Research: диапазоны цитат и технический поиск, 13 ноября 2026

Продолжение [V4](research-gates-2026-11-06.md), baseline `b29fd97`. D02/D04 восстановлены компонентным replay сохранённых исходников; это не новый retrieval recall. Общая приёмка остаётся открытой. Исторические failed результаты и независимый `request_changes` не отменены.

## Изменение

- Literal gate допускает полный quoted subject, включая `".invalid"`; предыдущая граница предложения, первичная RFC identity, целая клауза, точный witness и отдельный audit обязательны.
- Для вопросов с явным номером RFC draft выбирает `chunk_id,start,end` в Unicode code points относительно chunk. Приложение предлагает диапазоны предложений вместе с их исходным текстом и копирует исходный текст, включая переносы, самостоятельно. Буквальный RFC-claim строится из выбранного первичного диапазона только после прежней проверки полной клаузы; model prose не определяет его текст. Выбранный offset сохраняется даже при повторе одинаковой цитаты в chunk. Неверный/невидимый/слишком длинный диапазон отбрасывается прежними gates. Это внутренний model schema, публичные MCP input/output schemas не менялись. Нормализация переписанной цитаты не допускается. Для остальных вопросов прежний формат exact quotes сохранён.
- Запасной lexical selector для research добавляет в прежний пул окна от начала запрошенных Rust `pub fn` declarations; общий выбор по-прежнему ограничен тремя окнами по1200символов. Qwen selector, его strongest window и legacy ranked gates не менялись. Ограничение: другие синтаксисы declarations не добавлены без воспроизводимого miss.
- Планировщик API-запроса получает инструкцию искать язык и точный символ API без длинного перечня возможных ответов. При явном запросе документации допускается targeted site в исходной границе. Новых URL из справочника, источников, backend, зависимостей и дополнительных вызовов нет.
- В model schema draft повторены прежние ограничения Rust на длину claim, непустые facets/evidence и максимум4claims. Для конкретного API-входа явно разрешена инстанциация полного общего контракта как inference с исходной цитатой и rationale; пустые неподтверждённые placeholders требуется опускать, не легализовать.

Прежние бюджеты 2 forms/4 SERP/4 reads/4 Qwen/6 generations/180 s/24000 context chars/32 KiB, URL/DNS/IP/redirect/refusal guards и запрет кэширования verdict/final answers сохранены. Диапазоны — подсказки выбора, а не утверждение, что каждый фрагмент является полным/достаточным доказательством.

- Plain-text gate различает числовые массивы, безопасные half-open API ranges (`[at, len)`, `[0, at)`) и Markdown-ссылки/labels. Прежние отрицательные контроли ссылок/HTML сохранены.
- Уже audited partial claims сохраняются, когда последующие чтения не дали новых документов. Audit инвалидируется непосредственно при добавлении нового source, до await ранжирования; новый документ или failed final audit по-прежнему удерживает pending claims. Ошибка чтения не становится подтверждением отсутствующего условия.

Два разных тела не подменяются независимостью издателей.

Дополнительный Harness v4 не восстановил ответ: symbolic intervals были удержаны text gate, а последующие неудачные чтения сбросили уже audited partial. Эти причины покрыты последними regression tests; провал не скрыт и не засчитан как успех.

Component replay v5 показал неправильный выбор числовых границ без сопоставленного текста; final context связывает каждый диапазон с полным исходным текстом предложения. Это ограничивает ошибку выбора без подсчёта символов моделью.

Промежуточный component replay v3 провалился: модель перефразировала буквальный RFC-claim; final helper теперь выводит claim из выбранной первичной клаузы. Провалы, snapshot каждого собранного для проверки бинарника и повтор после transport loss сохраняются отдельно; повтор не является новым holdout. Ранний запуск ignored-теста с коротким именем и `--exact` выполнил0тестов и доказательством не считается; последующие команды использовали полное имя.

Живые Harness и отдельный model component replay отражены в [results](../feasibility/research-followup-results-2026-11-13.json). Снимок реализации, hashes, расходы, исходные результаты и актуальный source-state находятся там же. Новые отказы сохраняются поверх всего прежнего ledger, включая отказы 6 ноября.
