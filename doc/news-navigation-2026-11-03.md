## Поведение

Runtime — Rust, `request-evidence-v11-news`, startup `--evidence-memory`, прежние DeepSeek V4.1 Flash1017 через OpenRouter и локальный Qwen3-Reranker-0.6 B-4 bit. Новых поисковых/скрейпинговых API, браузерного рендеринга, моделей, VPS или глобальных настроек нет. Добавлена прямая ссылка на уже установленный Chrono0.4.45; других package/version изменений и загрузок не было.

- Для новостного намерения сначала рассматриваются найденные HTTP-кандидаты. Предпочтение корням/лентам позволяет не тратить первый слот на видеоканал. Один прочитанный feed может добавить до3 реальных same-origin ссылок на статьи; меню, темы, legal/app/download-навигация отсекаются до ограничения количества ссылок. Поддержаны длинные slug и числовые ID статей; короткий кириллический prefix помогает сопоставлять «Воронежа»/«Воронеже», но не подтверждает релевантность.
- Загрузка ленты расходует тот же общий предел **4 HTTP-чтения/3 generative/4 Qwen/180 с**. Уже прочитанные статьи передаются в Qwen, coverage и audit из памяти запроса. Дополнительных скрытых HTTP-чтений нет. Предел source JSON —24000 символов на модельный вызов. Search остаётся original-query Seznam+Naver без новых rewrite/fallback форм.
- Новостной direct требует прочитанную отдельную статью, подходящую полную дату публикации и прежний semantic audit с точными source witnesses. Лента, приложение, непрочитанный/недатированный источник, конфликт или будущая публикация не получают news-direct. Явные запросы поиска/скачивания приложения сохраняют исходный смысл; сообщение о выпуске приложения не отвергается за одно слово.
- Дата берётся из собственных Article/NewsArticle JSON-LD, article publication meta либо привязанного к основной статье publication DOM. Modified, Event, copyright, другая JSON-LD сущность и вложенный teaser не датируют статью. Отсутствующий год не восстанавливается из URL, вопроса или copyright. Доверенное календарное окно передаётся coverage/audit отдельно от веб-текста; исходная метадата даты — отдельный `D1…/publication_date` witness, который не может быть core-доказательством.
- «Сегодня»/«вчера» означают один день Europe/Moscow; поддержаны явный день/месяц/год и месяц/год. Без периода — последние3 календарных дня. Неоднозначные/неподдержанные диапазоны остаются недоказанными. Это проверка **даты публикации**, а не истинности каждого факта или времени описанного события.

В CLI/MCP сохранены прежние аргументы; ответ расширен `news_navigation` (окно, чтения, parent/href цепочки) и `results[].news` (исходные даты/причины допуска). `extract` возвращает тип/публикационные свидетельства без query-window. Новые сетевые переходы проверяют public URL/DNS/pinned IP и redirects; известный blocked host и чужой origin дочерней статьи отклоняются **до** DNS/HTTP следующего hop. Новая блокировка запоминается, ошибки чтения дают partial, а не скрытый ok.

Реализация: [news metadata](../src/news.rs), [bounded navigation](../src/news_search.rs), [policy](../src/policy.rs), [evidence/app gate](../src/evidence.rs), [HTTP guards](../src/net.rs), [контракт MCP](local-mcp.md).

## NEW8 и разметка

[Cases](../feasibility/news-navigation-cases-v1.json) и [plan](../feasibility/news-navigation-plan-v1.json) зафиксированы до вызовов. До inference исправлена черновая ошибка протокола: «сегодня» означает03.11, а не default01–03.11; старый draft сохранён. Порядок веток чередовался, два MCP-процесса сохраняли состояние. Baseline — сохранённый v10 release, candidate — свежий v11 release, оба с одинаковыми startup DeepSeek/Qwen. Источники/HTML **live, не идентичные замороженные inputs**; эффект одного reranker и причинный размер улучшения не выделяются.

Grade2 — отдельная публикация по месту/теме/периоду, подтверждённая полным оригиналом и собственной полной датой. Ленты/навигация — grade1, чужая тема/география/период — grade0, отсутствие нужного оригинала — unknown. Здесь неподходящий direct означает несоответствие этой news-rubric, **не ложность всех фактов на странице**. Полезность главных СМИ как следующего шага не отрицается.

Два участника команды размечали источники без arm/classification/audit, исходные оценки сохранили. Первые8 web-open дали только2 читаемых текста, не подтвердив перспективные статьи. После блокировки app-хоста первоначальный runner слишком широко остановил planned extra-validation. По явно записанному [дополнению](../runs/news-navigation-2026-11-03/benchmark/validation-amendment.md) выполнены23 отдельных source-validation запроса неизменённым Rust HTTP-клиентом с deny andro.io и строгим origin. Никаких новых поисков/модельных вызовов; уже ошибочные URL не повторялись. Получены22 HTTP200 originals,1 timeout; offline extraction дала21 полный текст, для NewsNN — no text. Исходный HTML сохранён, HTTP200 сам по себе не засчитывался как статья.

До соединения с predictions source-only v2 пересмотрела только строки с новым оригиналом: **76 unique case/URL,35 grade0/31 grade1/3 grade2/7 unknown**. Часть карточных0/1 остаётся предварительной (`source_reviewed=false`), все3 grade2 имеют full body и проверенные raw own publication fields. Один старый article-like Tatar URL фактически вернул общую ленту — grade1, дата соседнего teaser не перенесена. Две нижегородские статьи — один событийный кластер/один издатель, не два независимых подтверждения.

Первый анализатор отклонил3 нестандартных имени типа (`site_navigation/site_profile/channel`). До успешного подсчёта сделано только их отображение в согласованный enum; grades, даты, source evidence и исходные файлы аннотаторов неизменны. История normalisation и хеши сохранены. Это review текущей команды, не формальная независимая приёмка.

## Результат

Первичный MCP публикует хеши/ссылки, но не архивирует весь target HTML и внутренние model inputs. Original validation выполнена позже; она не является byte-identical replay первичного чтения. Parent→href цепочки проверены по наблюдаемому trace и успешным документным записям, без независимого восстановления исходного feed HTML для каждой цепочки.

Зафиксированы14 успешных observed parent→article цепочек;5 прошли runtime date gate, но этого недостаточно для семантической пригодности. В опубликованной выдаче manual source gold подтвердила3 подходящие страницы,1 получила direct. Публикационная дата и дата события различены. Две нижегородские страницы потеряны как direct на `evidence unused requirement`, а не на извлечении/датах.

Оставшиеся ограничения видны в этом же прогоне: nn05 `naver: parser_changed` у обеих веток; nn06 no-text/UTF-8 extraction errors у v11; nn07 fetch_timeout; nn08 source_blocked andro.io.
