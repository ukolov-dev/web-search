# OpenRouter для классификации — 30.10.2026

Пользователь явно запросил переход с локального oMLX на OpenRouter. Это разрешённое исключение из прежнего запрета сторонних LLM API. Поиск и чтение страниц по-прежнему идут через прежние Rust HTML-адаптеры; сторонние поисковые/скрейпинговые API не добавлены. VPS и глобальные настройки клиентов не менялись.

Общий Model использует существующий reqwest-клиент и тот же classify/review/audit pipeline. oMLX остаётся доступен со старыми аргументами. Для OpenRouter endpoint фиксирован: `https://openrouter.ai/api/v1`. Провайдеры взаимно исключаются; модель задаётся явно. Никакого fallback на другую модель или oMLX нет. HTTP redirects/retries отключены. `provider.require_parameters=true`, strict JSON Schema и прежние проверки evidence/ID/literals сохраняются. Локальные `chat_template_kwargs`/`tool_choice` не отправляются OpenRouter. Ошибки, включая HTTP 200 с error object, не принимаются за классификацию.

Ключ читается из указанного файла с закрытыми правами (на Unix group/other access запрещён, например 600). Его нет в аргументах MCP, diagnostics или ответе. Диагностические JSON дополнительно редактируются при совпадении с ключом; сообщение preflight-ошибки редактируется перед выводом; подробности remote generation error не выводятся. Локальные настройки авторизации и ключи в Project Context не записываются.

## Запуск

Сохранить ключ самостоятельно **вне проекта**, например в `$HOME/.config/web-search/openrouter.key`, с правами 600. Сам ключ не передавать в чат или аргументах команды.

```sh
./target/release/web-search mcp \
  --openrouter-key-file "$HOME/.config/web-search/openrouter.key" \
  --model deepseek/deepseek-v4.1-flash-1017
```

Тот же выбор доступен для диагностического CLI:

```sh
./target/release/web-search ranked-search 'ваш запрос' \
  --openrouter-key-file "$HOME/.config/web-search/openrouter.key" \
  --model deepseek/deepseek-v4.1-flash-1017 \
  --live --output runs/openrouter-first-query
```

`--omlx-settings` в MCP или `--settings` в ranked-search/ranked-suite сохраняют старый локальный режим и его default MiMo. Без provider-настроек MCP search/discover/extract работают, ranked_search возвращает model_unconfigured. Только startup-конфигурация выбирает модель; аргументы инструмента не управляют endpoint или ключом. В ranked-ответе добавлены model_provider/model. Сырые CLI-вызовы сохраняют usage от провайдера, включая cost при наличии; отдельного денежного лимита и постоянного учёта расходов здесь нет. Лимиты 3 model calls/180s сохранены.

В preflight исправлена потеря причины ошибки: HTTP-ответ теперь разбирает error как строку или объект, секрет редактируется **до** ограничения длины сообщения. Кто именно применил политику — OpenRouter или промежуточная среда — не установлено. Нет оснований объявлять ключ неверным, аккаунт заблокированным или модель недоступной по региону.

Суммарно за обе проверки: 4 API GET, 0 генераций, 0 поисковых и документных загрузок. 35 обычных тестов проходят после изменения диагностики. ## Доступ исправлен: существующий системный маршрут

Последующая диагностика исключила ключ как причину именно прежнего 403: **без Authorization** и главная страница, и `/api/v1/models` вернули Cloudflare 403. TLS-сертификат принадлежит openrouter.ai; в ответах есть Cloudflare Ray ID. Конкретное правило Cloudflare неизвестно; блокировку аккаунта или региона не утверждаем.

В macOS уже включён локальный HTTPS proxy, а OpenRouter-клиент использовал `no_proxy()` и всегда шёл напрямую. По существующему системному маршруту один GET без ключа вернул **200** и каталог с закреплённым DeepSeek. Исправление — явный startup-параметр `--openrouter-proxy`, только для OpenRouter. Он принимает HTTP loopback endpoint с явным портом, без userinfo, path/query/fragment. Это настройка маршрута до запроса; автоматического переключения после 403 или перебора proxy нет. Глобальная конфигурация macOS, oMLX и безопасный HTTP-клиент публичных страниц не менялись.

Рабочий запуск на проверенном Mac (порт взят из уже включённой системной настройки):

```sh
./target/release/web-search mcp \
  --openrouter-key-file "$HOME/.config/web-search/openrouter.key" \
  --model deepseek/deepseek-v4.1-flash-1017 \
  --openrouter-proxy http://127.0.0.1:10808
```

Параметр доступен также ranked-search/ranked-suite, требует OpenRouter key-file и не принимается через аргументы MCP-инструмента. При отказе локального proxy прямого fallback нет. TLS-проверка сертификата сохраняется; модельный Bearer передаётся внутри TLS, не в открытом CONNECT.
