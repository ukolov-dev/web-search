# Offline A/B: условия в evidence и минимальный пересказ API

**Оба варианта не проходят критерий улучшения на исторических случаях.** A снижает ошибки отказами, но теряет хорошие ответы. B помогает на синтетических коротких предложениях, однако на исторических данных добавляет ложное утверждение. Продуктовый runtime не менялся.

По поручению отдельно испытаны:

- **A — исходный контекст witness:** [expand](../scripts/witness-context-experiment.py) расширяет замороженную цитату до эвристически найденных полных предложений, иногда с непосредственным вводным абзацем на двоеточие. Claim не меняется. Это проверка доступности условий в собственном evidence, а не новая модельная проверка смысла.
- **B — extractive API:** [extract](../scripts/api-extractive-experiment.py) заменяет claim оригинальным предложением, содержащим тот же исходный witness. Допускается только нормализация пробелов в claim; quote остаётся исходным Unicode-срезом. Язык источника сохраняется. Это отдельный вариант, A helper он не использует.

Оба получают только full source text и document-global start/end; question, gold и ожидаемый ответ им не передаются. Варианты не выбирают другую цитату по gold. Source cap100000codepoints; quote12..360; B claim≤240. Если фраза не помещается или граница признана неясной — явный withhold без обрезки. Два helpers — независимые кандидаты, поэтому пересечение boundary-кода намеренно не сводилось в общую эвристику по совету refactor-review.

## Протокол и сохранённые данные

[16 замороженных строк/gold](../feasibility/witness-experiments-cases-2026-11-18.json), [результаты](../feasibility/witness-experiments-results-2026-11-18.json), [независимая разметка и code review](../feasibility/witness-experiments-quality-2026-11-18.json). [Driver](../scripts/witness-experiments-2026-11-18.py) проверяет SHA, original witness и диапазоны до вызова helpers, а после — точность source slice, containment и лимиты. Результат создаётся исключительно новым файлом; повтор поверх сохранённого результата запрещён.

Снимок эксперимента `27f2b5d20aaa8f903c72ae9bc87befd0e699cdef`; src/tests/Cargo.toml/Cargo.lock неизменны относительно `aaecc09`. Source/cases/inputs/gold/helper/driver hashes сохранены до корпусного запуска. Авторы A/B заявили, что challenge не читали; это процедурная независимость, не криптографическое доказательство отсутствия доступа. Один агент отдельно подготовил gold и оценил baseline/A/B, другой проверил код и воспроизвёл результаты.

Когорты различаются и **не объединяются**:

1. **Historical development8:** восемь сохранённых claim/witness, включая старые ошибки и положительные контроли. Исходный source body, hash и document_version сверены с прежними captures. Это известные development-данные, не новая независимая оценка поиска.
2. **Synthetic challenge8:** восемь коротких искусственных API-текстов с условиями, датой/областью действия, контрастом, несколькими предложениями, переполнением бюджета и Unicode. Это проверка компонентов, не эмпирический web holdout.

Каждая строка остаётся в знаменателе при withhold. Полные source bodies находятся только в excluded raw archive. Baseline — сохранённый исходный claim/quote, а не новый ответ модели. Ни HTTP, ни продуктовые LLM/Qwen не вызывались; OpenRouter после429 не повторялся. Refusal ledger из предыдущего прогона не изменён.

**Historical A — FAILED:** хорошие H05/H08 потеряны. False H01/H03 исчезают из выдачи вследствие withholding, а не исправления утверждений. Расширение witness само по себе не выполняет semantic audit. На synthetic C01/C04/C05 расширенный source показывает ограничение/противоречие, однако исходный false claim остаётся неизменным.

**Historical B — FAILED:** новый false **H02**. Ранее claim ограничивал сортировку целью собрать все равные ключи; извлечение literal sentence `Always sort...` превратило это в безусловное требование. Source-дословность здесь100%, мировая/контекстная правильность отсутствует. Потеряны хорошие H02/H07/H08; прежний false H03 убран, но это не компенсирует новый H02. Поэтому даже одинаковое суммарное число false2 не означает отсутствие регрессии.

**Synthetic B** лучше сохраняет явно записанное условие внутри короткой фразы: coverage1/15→9/15. Но C01 даёт факт для borrowed values вместо requested owned values, C04 — исторический факт вместо текущего ответа. Фраза может быть верной и всё равно не отвечать на вопрос. Этот положительный компонентный результат нельзя переносить на реальные web-ответы.

## Что это меняет в следующем шаге

Узкая идея извлекать полную фразу полезна как **кандидат evidence**. Превращать её сразу в окончательный ответ нельзя. Следующий обоснованный эксперимент: сохранить исходный scope/условие, затем отдельно проверить соответствие claim вопросу, фазе версии и времени. Продуктовый audit уже существует: следующий эксперимент должен проверять его вариант с явным разбором scope/time и силы условия в прежнем бюджете, а не добавлять ещё один вызов. В текущем offline A/B этот semantic этап не выполнялся и его эффективность не заявляется.

Для A важно различать: расширение контекста может сделать противоречие видимым, но не отменяет ложный claim автоматически. Для B важны current source authority и область применимости, а также сохранение хорошего условного парафраза вместо механической замены универсальным высказыванием из источника.

## Проверки и ограничения

Self-checks: A12, B9, caller проверяет Unicode, containment, подмену цитаты/claim и withholding. Независимый reviewer воспроизвёл все16 пар результатов A/B, сверил frozen SHA, исторические claims/source versions и исходные witnesses. Диапазоны и бюджеты соблюдены; семантические результаты получены отдельной агентской разметкой, не меткой `expanded` или `ok` helper.

Дополнительная диагностика code reviewer не включена в frozen16: A на `Use e.g. bytes when enabled.` возвращает `bytes when enabled.`, теряя вводную часть из-за сокращения. Это подтверждает, что пунктуационная граница не гарантирует полное условие; B в таком случае отказывается. После просмотра результатов эвристики не подгонялись.

Границы: A finite anaphora heuristic и punctuation splitter не являются языковым анализатором; B не проверяет актуальность/истинность источника; более одной quote bundle и перевод на русский не испытаны. Проверенные команды используют обычный `python3`: с `-O` assertions harness отключатся, такой режим не квалифицирован. Standalone B не является публичным сервисом; source cap обеспечивает caller. Большие входы `json.load` не проверялись как недоверенный сетевой endpoint.

Обязательные команды и их фактические исходы сохранены в Router verification. Rust suites не повторялись: runtime не менялся. Нет новых API, зависимостей, модели, public release, push, merge или deploy. Результат задачи — законченная проверка двух гипотез; продуктовые кандидаты не приняты.

Raw inputs, freeze, provenance и независимые reviews сохранены локально в `feasibility/witness-experiments-corpus-2026-11-18.tar.gz`; размер/SHA — в [манифесте](../feasibility/artifact-manifest.json). Это сохранённый корпус, не кэш финальных ответов продукта.
