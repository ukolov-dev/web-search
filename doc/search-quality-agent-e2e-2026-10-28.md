# Качество поиска и настоящий агент — 28.10.2026

**Вывод:** локальный MCP пригоден для экспериментов с агентом, но поисковая выдача пока не проходит порог ТЗ. По предварительной ручной разметке SERP у Bing прошли **9 из 20 запросов** при требовании минимум 16. Настоящий Codex CLI получил подтверждённый ответ в одном из двух полных сценариев. Во втором он сообщил о недостатке доказательств. С заранее заданными официальными URL второй вопрос был решён — в этом примере сбой локализован в получении релевантных страниц, а не в их чтении.

## 1. Границы и метод

Использован прежний исправленный набор v2 из 20 запросов: 10 RU / 10 EN. Запросы не переформулировались внутри набора. Правило [search-quality-rubric-v1.md](search-quality-rubric-v1.md) записано до нового прогона и следует шкале 0/1/2 из ТЗ: для успеха нужны минимум три уникальные органические страницы с оценкой 2. У каждого запроса запрошено до десяти результатов через реальный MCP stdio-клиент и финальный release-бинарник предыдущей итерации.

Релевантность оценивал этот агент по сохранённым title/snippet/URL. Это предварительная разметка кандидатов, а не независимая человеческая оценка и не прочтение всех найденных страниц. Неоднозначные материалы оценены консервативно. Копии и переводы одной страницы не увеличивают число уникальных результатов. Даже положительный исход такого прогона не заменил бы два живых прогона в разные дни и полную проверку ТЗ.

DuckDuckGo не запрашивался: в предыдущей пробе он вернул HTTP 202. Известные блокировки других источников не обходились. Поисковые API сторонних сервисов, браузерное чтение и VPS не использовались.

## 3. Полный сценарий настоящего агента

Использован установленный **Codex CLI 0.164.0** как внешний клиент локального MCP. Это не тест локальной модели oMLX. Запуски ephemeral, read-only, с временным рабочим каталогом, `--ignore-user-config` и `web_search=disabled`. MCP настраивался только аргументами отдельного запуска; глобальная конфигурация не менялась. Поля stdio-подключения и CLI-параметры сверены с [официальной документацией MCP](https://learn.chatgpt.com/docs/extend/mcp#stdio-servers) и [codex exec](https://learn.chatgpt.com/docs/developer-commands#codex-exec).

Модель клиента использовалась по умолчанию CLI и отдельно не закреплялась. Системный контекст клиента и его токены не характеризуют стоимость будущего research в oMLX. Подробные usage, хеши событий и фактические вызовы сохранены в машинном отчёте.

Два вопроса и обязательные факты зафиксированы до запуска в [agent-e2e-cases.json](../feasibility/agent-e2e-cases.json). Агенту разрешены максимум два search, один extract с максимум тремя URL из полученной выдачи. Другие инструменты и встроенный поиск запрещены инструкцией теста; по фактическим событиям подтверждено использование только нашего MCP. Все опубликованные в ответе базовые URL сопоставлены с успешно прочитанными документами; якоря фрагментов отдельно не проверялись.

| Сценарий | Вызовы | Результат | Время |
| --- | --- | --- | ---: |
| RU: перенос владения String, Copy и clone | 1 search + 1 extract | 3/3 обязательных факта подтверждены текстом Rust Book; ответ со ссылками | 23,69 с |
| EN: конкурентность и снимок в SQLite WAL | 2 search + 1 extract | 0/3 фактов доказаны; честное сообщение о нехватке материалов | 29,34 с |

Во втором случае запрос с `site:sqlite.org` дал страницы про китов — немецкое Wal, а следующий запрос с URL isolation.html вернул общие страницы SQLite. Агент прочитал homepage/download и не стал выдавать неподтверждённые утверждения о WAL. Это **не содержательно успешный ответ**, даже при корректном отказе от выдумывания.

В успешном Rust-случае проверены перенос владения и недействительность s1, отсутствие Copy и причина защиты от double-free, отдельное копирование через clone. Дополнительное объяснение ссылок согласуется с заключением прочитанной страницы о доступе без передачи владения. Для проверенных утверждений в отчёте сохранены хеши текста и диапазоны Unicode code points в извлечённом тексте. Это ручная диагностическая привязка, а не реализация полного контракта claims приложения.

## 4. Диагностика SQLite с готовыми доказательствами

После неудачи проведён отдельный oracle-тест по [agent-oracle-sqlite.json](../feasibility/agent-oracle-sqlite.json): тот же вопрос, но агенту заранее переданы официальные WAL и isolation URL. Он выполнил только один extract, прочитал обе страницы и подтвердил **3/3 факта**: совместную работу читателей и писателя, одного писателя за раз и сохранение снимка активной read-транзакции. Время — **20,94 с**.

Этот результат **не засчитывается как успех поиска или второй полный e2e-сценарий**. Он показывает, что для данного вопроса извлечение и формирование ответа работают при наличии нужных страниц. Чувствительность выдачи к формулировке и отбор URL агентом остаются важными частями проблемы retrieval.

События, ответы, вопросы, бюджеты, контрольные суммы и ручная оценка фактов: [agent-e2e-results-2026-10-28.json](../feasibility/agent-e2e-results-2026-10-28.json). Полные локальные журналы и точные промпты — `runs/agent-e2e-2026-10-28/`.

## 5. Решение и следующая работа

1. Сохранить MCP search/extract как экспериментальные инструменты. Не объявлять текущий Bing основным квалифицированным источником.
2. Следующей задачей проверить передачу и обработку поисковых операторов, особенно site, и поведение альтернативного HTML-источника без обхода его ограничений. Настройки сравнивать с сохранённым baseline; не менять исходный набор незаметно.
3. В агентском сценарии проверять соответствие полученных URL запросу до чтения. Для известной официальной документации допустимо прямое чтение заранее известного публичного URL, но его нужно явно отличать от результата поиска.
4. После улучшения retrieval повторить оценку по тем же правилам. Затем развивать кэш и research; увеличение числа вызовов модели само по себе не исправляет чужую выдачу.

Добавлен отдельный ignored-тест `live_bing_quality_capture`, который собирает данные и останавливается при блокировке. Его зелёный статус означает успешный capture, а не достижение порога релевантности. Повторная проверка кода: fmt и clippy с `-D warnings` прошли; обычный cargo test — **11 passed, 3 ignored**. Браузер, общий живой smoke и capture запускаются явно; в этой итерации отдельно выполнен только capture. Серверный код не менялся.

Полный пилот не принят: нет второго пригодного источника, второго дня измерений и полной проверки остальных требований. Prompt injection, полный контракт доказательств, кэш, браузерный шлюз, oMLX research и Linux/VPS этим прогоном не квалифицированы.
