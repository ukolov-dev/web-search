## Почему F09/A3 блокирует приёмку

V6 дополнительно к ответу про пустой Vec выпустила `Vec::pop` takes O(1). Quote `Takes O(1) time.` встречается дважды в видимом S1P1. Non-RFC draft задаёт chunk_id+quote, а Session::quote при selected_start=None выбирает первое совпадение через text.find. В возвращённом диапазоне это сложность **push_within_capacity**, перед объявлением pop. Правильная такая же фраза для pop находится далее в том же прочитанном chunk.

Таким образом, различаются три проверки: исходный Unicode slice точный; факт про pop поддержан прочитанным контекстом; **возвращённая привязка к нужному API неверна**. Последнее учитывается как unknown support по возвращённому witness, а не как фактически ложная сложность pop. [Разметка](../feasibility/qwen-acceptance-quality-2026-11-13.json) сохраняет оба диапазона, document_version и окружающий текст. RFC selected_start этот случай не исправляет: здесь используется прежний non-RFC путь.

Во время этого прогона runtime оставался замороженным. После отдельной фиксации результата F09 использован как development regression для V7; тот же F-набор не выдан за свежее подтверждение. Для следующей доработки нужен regression на повтор цитаты у разных API и точная привязка выбранного non-RFC witness; затем отдельное подтверждение качества. Само наличие верной фразы в другом месте не исправляет уже возвращённый диапазон.
