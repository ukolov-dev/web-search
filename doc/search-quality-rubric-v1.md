# Правило оценки поисковой выдачи v1 — 28.10.2026

Правило фиксируется до нового живого прогона. Используется неизменённый исправленный набор v2: [search-cases.json](../feasibility/search-cases.json), 20 разных запросов, 10 RU / 10 EN. Ранее этот набор полностью не прогонялся; результаты v1 не подменяются.

Через настоящий MCP stdio-клиент запрашивается max_results=10 у Bing. На запрос выполняется один вызов; между вызовами пауза не менее двух секунд. При CAPTCHA/202/403/429 источник останавливается, оставшиеся случаи отмечаются пропущенными и не засчитываются. DDG уже получил HTTP 202 в предыдущей пробе; новый запрос не выполняется. Полный ответ инструмента, исходный запрос, хеш набора и бинарника сохраняются до оценки.

Ручная оценка агентом использует заголовок, сниппет и URL каждой органической ссылки:

- **0:** не относится к конкретному запросу, относится к другому значению слова или нарушает обязательный site-фильтр.
- **1:** полезный фон, но из выдачи не видно прямой помощи с вопросом; неоднозначный/неполный/устаревший материал.
- **2:** заголовок и сниппет явно указывают на материал, непосредственно помогающий ответить на запрос, с соблюдением ограничения домена/времени, если оно задано.

Это предварительная оценка кандидатов по SERP, не верификация содержимого всех страниц и не независимая человеческая разметка. При сомнении ставится 1. Для меняющегося сведения без подтверждённой даты/периода нельзя ставить 2. Для полного сценария агента отдельно оцениваются прочитанные страницы и поддержка фактов в ответе.

Для каждого запроса посчитать уникальные страницы с оценкой 2. Копии/редиректы одной страницы не увеличивают счётчик; разные страницы одного домена допустимы. Успешный случай требует минимум трёх таких страниц. Порог из ТЗ — минимум 16 из 20 случаев в каждом из двух прогонов в разные дни. Этот первый диагностический прогон сам по себе не закрывает приёмку, даже при достижении 16/20. Если предварительная оценка ниже порога, считать источник неквалифицированным; один удачный пример не заменяет набор.
