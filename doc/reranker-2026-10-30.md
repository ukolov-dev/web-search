# Локальный Qwen3-Reranker-0.6B: реализация и A/B, 30.10.2026

> Уточнение 30.10 после разбора сырых ответов: семь initial failures полного12 — это **6 length и 1 stop с пустым content**, а не7 length. Исходные измерения качества ниже сохранены. Последующий initial/relational fix и отдельный полный свежий8 A/B описаны в [новом отчёте v4](reliability-full-search-2026-10-30.md); они не переоценивают этот исторический прогон.

Локальный reranker подключён и работает из Rust через установленный oMLX. Он улучшил попадание опорного текста в выбранные passages, но **не изменил итоговые direct labels**. Оставлен opt-in; default legacy не изменён. Повышение recall поиска или исчезновение ложных direct этим прогоном не доказаны.

## Что реализовано

- Установлен `mlx-community/Qwen3-Reranker-0.6B-4bit`, MLX affine4bit/group64,346774989 байт. Runtime oMLX0.7.0. После тестов MiMo9B и Qwen одновременно загружены, active/waiting/loading=0; чужие модели не выгружались, сервер не перезапускался, глобальные настройки не менялись.
- Rust startup `--evidence-memory --reranker-settings <local settings file>`; reviewer остаётся DeepSeek V4.1 Flash1017 через ранее разрешённый OpenRouter. Фиксированный local model ID, loopback-only `/v1/rerank`, no proxy/redirect/retry. Адрес/ключ/режим не принимаются как MCP tool args. Runtime не скачивает веса.
- Из полного извлечённого тела, ограниченного100000 code points, строятся окна1200 с шагом1000 до самого хвоста (max128). Scoring идёт **до** усечения до3 passages. Сохраняются исходные нормализованные bytes ranges и hashes, текст не переписывается. Перекрытие выбранных окон меньше50% меньшего.
- Score не является вероятностью истинности и не устанавливает `direct`. Coverage, literal/site/provenance guards и первый classifier не изменены. Даже score1 не отменяет gate.
- Дополнительно к пределу3 generative calls: max4 local rerank calls, один на успешно извлечённую страницу, max30 с каждый внутри общего180 с. Бюджет виден в `reranker_calls/reranker_pairs`. HTTP/timeout/неполный/неверный response → observable `lexical_fallback`, прежний selector и тот же gate. Валидируются model, все уникальные indices, finite scores0..1; response ограничен64KiB, включая chunked чтение.

Код: [selector](../src/reranker.rs), [transport](../src/model.rs), [общая память](../src/evidence.rs), [startup](../src/main.rs), [benchmark](../src/reranker_benchmark.rs). Команда запуска — в [MCP-контракте](local-mcp.md#локальный-passage-reranker-opt-in-30102026).

## Дизайн эксперимента и разметка

Сравниваются **coverage-v2 с текущим lexical selector** и **тот же coverage-v2 с Qwen**. Это не сравнение с legacy default. Общие SERP, candidate IDs/RRF, первый review, anchors и выбранные для чтения страницы сохранены один раз. Второй review вызван отдельно для каждой ветки; порядок lexical/Qwen чередуется. Gold не передавался моделям.

1. Полный12: новые строки запросов зафиксированы до ответов.228 карточек,24 логических search attempts. Семь initial classifier outputs завершились `length`; прежняя настройка high/max2400 сохранена. До coverage дошли5/12. Пять тем повторяют механизмы прошлых development-наборов, поэтому это диагностический development-прогон, **не новый независимый holdout по темам**.
2. Отдельный component8: зафиксированы8 других, ранее не проверявшихся механизмов — weakref.finalize, Condvar, concurrent index failure, journal_size_limit, tmpfs, flex minimum, git restore, If-Range.114 карточек,16search attempts. Для изоляции selector upstream зафиксирован: все RRF-кандидаты предварительно background, первый coverage review общий. Initial classifier здесь **не запускался**. Это компонентный эксперимент, его recall нельзя выдавать за recall опубликованного полного поиска.

Оба источника отвечалиHTTP200; в component8 один Naver response имел `parser_changed`, другие39 source responses пригодны парсеру.52runtime read attempts дали45 извлечённых документов. Известные host blocks сохранены; обходов CAPTCHA/прокси/браузерного доступа не было. Дополнительно12 найденных официальных страниц прочитаны только для слепой gold-разметки; они **не попали** в contexts веток.

Один автор разметил сохранённые snapshots до запуска A/B:37/114 карточек component,31/228 полного набора. Grade2 означает конкретную помощь требуемой связи; grade1 — неполную поддержку в реально извлечённом тексте;0 — нерелевантность; null — неразмеченное. Полнота разметки ограничена; это recall **известных релевантных найденных источников**, а не universal web recall. Неразмеченные direct отдельно считаются unknown, не превращаются в FP или TP. Неполное извлечение страницы способно оставить фактически подходящий источник без подтверждённого gold-positive. Источники, опровергающие неверную предпосылку, могут быть полезны; direct не означает согласие с предпосылкой.

Для passage-метрики вручную выбраны дословные опорные цитаты с hashes и offsets. Hit@3: хотя бы одна целая опорная цитата попала в выбранные окна. All-support@3: попали все размеченные опоры данной страницы. Это операциональная проверка конкретных цитат, не полная семантическая приёмка; ненаписанные альтернативные объяснения могут быть полезны. Метрика включает только positive-страницы, действительно прочитанные runtime. Во всех выбранных body passages анализатор проверил текст/диапазон/raw hash/normalized hash; title/snippet и fixed requirements в A/B совпадают.

## Основной результат: component8

| Метрика | Lexical | Qwen |
|---|---:|---:|
| Известные релевантные источники | 15 | 15 |
| TP / FP / FN | 8 / 3 / 7 | 8 / 3 / 7 |
| Recall direct | 53,3% | 53,3% |
| Precision среди размеченных direct | 72,7% | 72,7% |
| Неразмеченные direct | 0 | 0 |
| Passage hit@3 | 11/13 (84,6%) | 12/13 (92,3%) |
| All-support@3 | 6/13 (46,2%) | 10/13 (76,9%) |
| Покрытие размеченных опор | 15/22 (68,2%) | 19/22 (86,4%) |
| Медиана модельно-документных этапов | 6,58 с | 9,02 с |

Все предсказанные sets direct совпали **для каждого** вопроса, а не только в сумме. Поэтому разница recall0 п.п.; bootstrap по этим данным вырождается в0 и не доказывает нулевой эффект на других запросах. Три FP относятся к одному h08 и к языковым версиям одной статьи, а не к трём независимым ошибкам. На уровне вопросов FP есть в1/8 в обеих ветках.

| Вопрос | Direct в обеих ветках | Наблюдение |
|---|---|---|
| h01 weakref | C009 | Нужный источник остался на общем первом review; body rerank его не затронул |
| h02 Condvar | C002,C006,C007 | Полезные docs и source comments доступны обеим веткам |
| h03 concurrent index | C007 | Улучшенное покрытие не добавило уже имевшийся direct повторно |
| h04 journal_size_limit | — | После Qwen остаются coverage gaps R2 и literal gaps на другом источнике |
| h05 tmpfs | — | Требования R2/R3 остались missing; выбор фрагментов не снял gate |
| h06 flex minimum | — | Части нужной связи есть, но cited passages не проходят min-width/min-content requirements |
| h07 git restore | C006,C007,C009 | Одинаковые direct на двух английских и французской версии |
| h08 If-Range | C002,C009,C010 | Три false direct: общая статья о conditional requests вместо точного ограничения If-Range |

**Причина FP h08:** reviewer связывает If-Range с упоминаниями strong/weak validators и правилами соседнего If-Match. Статья содержит все слова, но не явную необходимую связь «weak ETag запрещён именно в If-Range». Qwen выбирает более тематические окна и не исправляет эту подмену отношения. Gold-positive C005 — конкретная страница If-Range — был найден, но не прочитан из-за общего read budget. Это ещё и ограничение выбора документов до reranker.

Здесь установлено **минимум2 false direct плюс3 непроверенных direct**, а не «всего2FP». Итоговые labels также полностью совпали. Семь `length` failures не скрыты и не перезапускались с более удобной настройкой. Историческая pathlib issue про RuntimeError не достаточна для современной семантики strict/symlink loops; общий asyncio guide не заменяет требуемую явную разницу gather/TaskGroup. Более полная source-разметка может изменить абсолютные метрики, но не наблюдённое совпадение A/B labels.

## Цена, время и доказанный путь

- A/B:45 локальных scoring calls,961query/passage pairs,346367 tokens; **0fallbacks**. Component:30 calls,661 pairs, median532 мс/call; полный12:15 calls,300 pairs, median585 мс/call. Это смешанные длины окон и количество пар, не token throughput benchmark.
- Генеративных физических calls в двух capture+comparison:51. Известная стоимость OpenRouter **$0.010433660**; component$0.003359202, полный12$0.007074458. Общие первые этапы оплачены один раз. Три дополнительные генерации release MCP smoke не включены: публичный MCP результат не содержит их usage.cost; неизвестную стоимость не считаем нулевой. Локальный scoring не использует платный внешний API.
- Timing A/B складывает elapsed общих model calls и document records с фактическим временем replay-ветки; retrieval не включён. Это диагностические этапы, не изолированная end-to-end latency. Два comparison jobs перекрывались по времени; possible server/provider contention. Медианная прибавка component+2,44 с не является гарантией SLA.
- Release `ranked_search` через настоящий stdio MCP выполнил3 локальных rerank calls/43 pairs,3 generative calls и4read attempts. Ответ `partial`: один fetch_timeout и одно прежнее grounding downgrade. Тест проверил интеграцию и реальные Qwen calls, **не** чистую доступность всех источников.
- После A/B добавлено потоковое ограничение64KiB для ответа reranker до накопления oversized body. Алгоритм и successful payloads не менялись; исходники A/B сохранены отдельно от финального source snapshot, повторный local Rust smoke и offline/release checks проверяют финальный transport.

## Проверки и следующие решения

Проверки финальной версии: cargo fmt, обычные offline tests, all-targets clippy `-D warnings`, release build, stdio tests свежего release, local Rust inference smoke, corpus/gold/provenance asserts и context checks. Точные команды, количество tests и результаты сохранены в verification evidence задачи `TASK-20261030-162019-001`. Refactor heuristic не получил Git diff из-за отсутствия репозитория; сделан собственный source diff review, независимой приёмки нет.

Оставляем Qwen дополнительным opt-in selector: выигрыш покрытия есть, выигрыша final recall нет. Следующий отдельный шаг — исправить связь subject/relation/qualifier в coverage judge и восстановить корректное завершение initial classifier, затем проверить на следующем неизменявшемся наборе. Простое увеличение числа passages или порога score не устраняет показанную ошибку If-Range/If-Match. МиMo+Qwen по качеству, VPS, load, day2 и общая qualification пилота не проверены.
