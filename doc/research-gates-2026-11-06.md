Три исходных дефекта исправлены в Rust: ошибочная RFC-атрибуция из вторичного источника блокируется, одна плохая citation больше не уничтожает хорошие witnesses, числовые массивы и индексы проходят проверку текста. **Приёмка качества не пройдена:** на финальном отдельном наборе покрытие фактических условий выросло **8/20→11/20**, но потеряны поддержанные baseline результаты **D02 и часть D04**. Ложные утверждения внутри FINAL12: **0→0**, unknown: **1→0**. Общий прирост не отменяет потери конкретных положительных контролей.

Реализация присутствует в проверенном снимке V4; задача остаётся `in_progress`. Независимый reviewer дал `request_changes`. Merge, выпуск, deploy, VPS и изменение глобального Harness profile не выполнялись; legacy ranked_search не менялся.

## Что изменено

1. `prune_invalid_claims` отбрасывает плохие citations по одной, сохраняет точные, затем проверяет весь claim и передаёт его в прежний отдельный audit. Ноль пригодных witnesses, неизвестные facets и неверная структура по-прежнему блокируют утверждение. Есть mapping draft→audit ID и причины исключений.
2. Разрешены числовые `[]`, `[1, 2]`, `a[0]`; ссылки, подставные reference labels и HTML остаются запрещёнными. Исходные цитаты не исправляются нормализацией. `document_version` у chunk и source должен совпадать.
3. RFC-атрибуция допускается как `RFC N: ` и полная дословная клауза прочитанного первичного документа. Rust связывает официальный конечный URL с собственным номером документа; роль не задаёт модель. Проверяются отрицание, целая числовая идентичность и границы среза, включая запрет обрыва внутри версии `TLS 1.2`. Это ограниченная буквальная проверка, а не универсальный анализ нормативного смысла.
4. Legacy HTML с пустыми title/heading допускается по точному раннему `Request for Comments: N`; противоречащий номер в собственных метаданных блокирует роль. Modern fallback требует отдельную строку `RFC N`, а не произвольное упоминание. Официальный-looking hostname сам по себе недостаточен.
5. Для RFC-запросов официальные `/info/rfcN` и Datatracker `/doc/rfcN` адресуются к тексту того же RFC внутри прежнего бюджета. Повторная site-проверка не расширяет caller boundary; при site:/info сохраняется info-адрес. Важно: info-URL сам по себе не доказывает отсутствие или наличие нормы в фактически прочитанном теле — ранний gate отвергал такие адреса, а не устанавливал отсутствие текста.
6. Модель явно получает допустимые zero-based `facet_indices`; неизвестные/пустые индексы не перенумеровываются и не легализуются. Audit видит все chunks, видимые draft, включая материал исключённой citation; conflict quarantine сохраняется. Используется именно `audit_visible`.

Публичные input schemas, startup providers, Qwen selector/3slots, URL/DNS/IP/redirect/refusal guards, source-state, cache TTL и запрет кэширования final answers/verdicts сохранены. На вызов по-прежнему2forms/4SERP/4reads/4Qwen/6generations/180с/24000context chars/32KiB. Новых API, browser/backend, persistent verdict memory или зависимостей нет.

## FINAL12: качество

Размечены11фактических вопросов с20условиями; D12 — отдельная проверка честного отказа по неподтверждённому API. Подстановка входа вопроса в полностью подтверждённый общий контракт операции засчитывается одинаково обеим ветвям (swap/skip/split_last). Фоновая справка и повтор одного аспекта coverage не увеличивают.

| --- | ---: | ---: |
| Выпущено claims | 9 | 14 |
| Поддержано целиком | 8 | 14 |
| Ложные claims | 0 | 0 |
| Unknown/неоднозначные claims | 1 | 0 |
| Покрытые фактические условия | 8/20 (40%) | 11/20 (55%) |
| Полностью покрытые фактические вопросы | 4/11 | 5/11 |
| Честная недостаточность D12 | 1/1 | 1/1 |
| Формальный status=ok | 0/12 | 0/12 |

Baseline D03/A1 с «MUST касается лишь совпадения X» окончательно оставлен **unknown_scope_ambiguous**. Глобальное прочтение противоречит другим MUST в RFC6238; исходный вопрос допускает узкое прочтение о выборе шага. Первоначально рассмотренный false-ярлык был слишком сильным; история исправления сохранена в [quality](../feasibility/research-gates-quality-2026-11-06.json). Истинные куски неоднозначного whole claim не превращались в TP.

Прирост: D05 +2аспекта, D08 +1, D09 +2. Потери: **D02 −1, D04 −1**. Приёмочный no-loss gate **failed**, даже при нуле новых false/unknown IDs.

Оставшиеся причины проверены по raw drafts:

- **D02:** правильная `.invalid`-клауза начинается кавычкой; текущая консервативная проверка начала клаузы допускает лишь uppercase/digit и ошибочно удерживает её. Текст и первичный источник доступны.
- **D03:** draft-рекомендация снабжена более широкой точной двухфразовой цитатой, чем буквальный claim; равенство не проходит. Сохранённая фраза про balance default30 верна, но не отвечает на RECOMMEND/MUST.
- **D04:** модель меняет исходный перенос/отступ в цитате правила exp-before. Exact отказ корректен; подгонять выдуманную копию нормализацией нельзя. Сохранилась только норма о leeway.
- D01/D06/D11 остаются без подтверждённого ответа. Empty/partial не доказывает отсутствия нужного знания в интернете.
