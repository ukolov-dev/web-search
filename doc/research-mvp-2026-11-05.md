# Bounded research: Rust MCP/CLI, 5 ноября 2026

По выбору пользователем пункта3 реализован локальный `research`: поиск уточняет запрос по недостающему аспекту, дочитывает источники и возвращает проверяемые утверждения, конфликты и пробелы в одном бюджете. Это экспериментальный контроллер, **не общая qualification поиска**. На шести development-вопросах все ответы остались `partial`; точность цитат подтверждена, полнота и надёжность семантического аудита — нет.

Реализация: [research.rs](../src/research.rs), [MCP](../src/mcp.rs), [CLI](../src/main.rs), [регрессии](../src/research_tests.rs). [Полный контракт и запуск](local-mcp.md#bounded-research--5-ноября-2026).

## Реализованное поведение

Один Rust-контроллер выполняет до двух проходов. Планировщик выделяет обязательные аспекты; после чтения кандидатов черновик предлагает атомарные утверждения с точными цитатами, а отдельный модельный вызов проверяет их поддержку. Rust валидирует ID, исходные срезы, выводы/rationale и собирает ответ со ссылками. Отсутствие цитаты не считается поддержкой: такой кандидат удерживается, при наличии бюджета поиск продолжается. Новое свидетельство требует повторного аудита; активный конфликт исключает утверждения соответствующего аспекта. При сбое сохраняются сведения о прочитанных источниках; непроверенные заново утверждения не выдаются как готовый ответ.

Общий предел на request: **2 формы / 4 SERP / 4 чтения / 4 Qwen / 6 генераций / 180с**. Загрузка ленты, ошибки и cache hits входят в логические лимиты. На генерацию передаётся не более24000 Unicode code points всего контекста; для финального audit резервируются вызов и время. Единственная schema-repair попытка также расходует6. Дочитывание не вызывает вложенный `ranked_search` с новым бюджетом. SSRF/DNS/IP/redirect/site guards переиспользуются; блокировка сразу обновляет общий host guard. Запрещённые источники не обходятся.

Новостные документы проходят прежний own-Article/date gate по **исходному** вопросу. Feed→article использует настоящую same-origin ссылку и общий бюджет чтений. Qwen выбирает фрагменты из исходного извлечённого текста; возвращаемые citation/answer offsets — Unicode code points, не normalized byte offsets старого ranked_search. Публичные данные ограничены32KiB UTF-8; полные тела, Qwen scores и model payloads доступны только через явный trusted capture. При переполнении ответ удерживается целиком, без оборванных цитат. MCP стандартно дублирует text и structured JSON: суммарный wire может быть больше32KiB.

`ok` требует полного покрытия, положительного отдельного аудита, отсутствия конфликтов и двух разных цитируемых тел документов. Повтор одного тела по разным URL не даёт второй источник; независимость издателей отдельно не установлена. `partial` может содержать полезные факты при оставшихся пробелах. Модели/ключи/provider URL/budgets задаёт startup. Новый `cache_mode=refresh` действует в пределах задачи и не меняет поведение последующих инструментов.

## Протокол и изменения в ходе разработки

Сначала сохранены исходники, release binary и SHA-256 исходных20/B17. Перед inference зафиксированы [четыре вопроса и reference-aspects](../feasibility/research-mvp-cases-2026-11-05.json); официальные страницы использовались для ручного gold, их URL **не передавались продукту**. Перед отдельным подтверждением зафиксированы [ещё два вопроса](../feasibility/research-mvp-confirm-cases-2026-11-05.json). Это development, а не слепой holdout или парное сравнение политик. Результаты разных сборок не объединяются в quality score. В R01 первая postprocessing-проверка указала неверный ordinal capture-каталога и завершилась ошибкой; исправленная проверка перечитала уже сохранённые данные, без повторения живого запроса. Исходный traceback сохранён.

Все вызовы использовали явно разрешённый OpenRouter `deepseek/deepseek-v4.1-flash-1017`, optional local `Qwen3-Reranker-0.6B-4bit`, существующий безопасный HTTP/extractor и opt-in SQLite. Новых providers/dependencies нет. Начальная refusal ledger взята из предыдущего Harness-прогона и сохранялась между всеми процессами.

В R01/R02 обнаружилась ошибка wiring: selector получал генеративную модель вместо `model.reranker`, локальная проверка отклоняла вызов и включался lexical fallback. Qwen: по1 логической попытке, **0 физических запросов**. Эти исходные результаты и код сохранены. Исправлен выбор локального reranker, добавлен конкретный loopback transport test. R03/R04 уже выполнялись с исправлением. В R03 модель предложила утверждение с пустым evidence; первоначальная версия завершала research с `model_error`. Финальная версия удерживает отдельный некорректный кандидат и продолжает в общем бюджете. R05/R06 проверяют эту версию на новых вопросах.

После проб добавлено немедленное распространение новых host-блокировок и запоминание фактически проверенного redirect-host; уточнение неограниченного вопроса может безопасно сузить поиск через site:, не расширяя исходный пользовательский site-boundary; пройдены offline/loopback/fresh release stdio проверки. Полная живая серия после этой охранной правки не повторялась. Последние дополнительные изменения — два offline-теста dedup/multiline quotes и исправление same-origin адреса в news fixture; runtime selection не менялся.

Это проверка происхождения, а не истинности.

Оценка содержания проведена исполнителем по источникам, не независимым reviewer. Точный разбор каждого вопроса — [results/quality](../feasibility/research-mvp-results-2026-11-05.json):

- **R01 — реальный риск аудита.** Принято «ресурс больше никогда не будет доступен», хотя [RFC9110§15.5.11](https://www.rfc-editor.org/rfc/rfc9110.html#section-15.5.11) говорит о вероятной постоянности. Цитата вторичного источника действительно содержит более сильную формулировку; отдельный судья её принял. Уточнены общие инструкции о qualifiers/официальных первоисточниках, но безопасное исправление этого класса ошибок ещё не доказано. Данные R01 не переписаны.
- **R02 — содержательная помощь, неполная доказательная база.** Утверждения о COUNT, пустом ответе и завершении по cursor0 соответствуют frozen reference, однако опираются на один Dragonfly guide. Оригинальная [документация Redis SCAN](https://redis.io/docs/latest/commands/scan/) не была доступна нашему HTTP-клиенту; второй полезный цитируемый документ отсутствует. Это не полный успех.
- **R03 — защита сработала, recall потерян.** Модель не дала цитату при наличии прочитанного контекста; ничем не подтверждённый факт не выпущен. Это не доказательство, что нужного фрагмента нет в источнике. [Python reference](https://docs.python.org/3/library/statistics.html#statistics.median_low) остаётся gold, не oracle-input.
- **R04 — честная нехватка.** Прочитанные даты вне окна, город/тема не подходят. Верных событий и дат в ответе0; отсутствие статей во всём интернете не установлено.
- **R05 — отличие методов видно, audit консервативен.** [RFC7538 abstract](https://www.rfc-editor.org/info/rfc7538/) и вторичные страницы поддерживают различие301/307, но не заменяют чтение текущего нормативного [RFC9110§15.4.8](https://www.rfc-editor.org/rfc/rfc9110.html#section-15.4.8). Возвращены также необязательные сведения о308. Наличие4 утверждений не превращает `partial` в выполнение всего вопроса.
- **R06 — отказ выдумывать ответ.** Цитат для SSCAN не хватило,4 некорректных кандидата удержаны. Поисковая выдача принесла в том числе SSL/форум/чужой architecture document; дополнительный раунд не исправил retrieval.

`direct`, `direct recall` и false-direct здесь не измеряются: новый инструмент возвращает атомарные утверждения, а не ranked labels. Полный corpus recall и доля ложных утверждений для общей популяции неизвестны. Результаты исходных20/B17 не изменены.

## Проверка реального Harness

Использован ранее установленный pinned DeepSeek Harness SDK0.2.2-rc.1 и Node24.22.2 в **отдельном** SDK profile. Native capabilities скрыты; guard допускает один настоящий `research`. Пользовательский глобальный профиль не редактировался. Эпизод завершён за **37,272с**: один research, две внешние генерации Harness, ещё **USD0,000286434** по usage.cost. Их бюджет/стоимость не входят в6 внутренних вызовов research; межвызовный общий бюджет агента ещё не реализован.

Ни одного tool-output spill не найдено. Агент увидел компактный ответ и сообщил о пробелах. При этом внешний ответ содержит собственные неточности: назвал все документы нерелевантными, хотя guide по SCAN может быть полезным фоном, и сократил URL форума. Внешний ответ Harness не проходит внутренний audit research. Один эпизод подтверждает подключение и транспорт, не качество всех ответов.
