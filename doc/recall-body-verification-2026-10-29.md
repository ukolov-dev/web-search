# Восстановление recall через текст страниц — 29.10.2026

В Rust `ranked_search` добавлено ограниченное чтение background-страниц с проверяемыми цитатами. На финальных восьми новых запросах собственная оценка дала **recall меток direct 40% → 45%, FP 2 → 2**. Это одна корректная переклассификация; состав пригодных страниц в top-10 и число успешных top-10 случаев не улучшились. Эффект небольшой, а стоимость чтения заметна.

Машинная сводка: [результаты](../feasibility/recall-results-2026-10-29.json), [все суждения и основания](../feasibility/recall-judgments-2026-10-29.json). Это оценка автора реализации, не независимая приёмка.

## Что реализовано

После исходного консервативного SERP-classifier читаются до четырёх background-кандидатов в порядке RRF. Каждый проходит общий HTTP-клиент и extract: публичные URL/DNS/IP, проверка редиректов, прежние лимиты размера и времени, без браузера и повторов после блокировки. Site проверяется до чтения и по конечному URL. Заблокированные документные хосты запоминаются в MCP-процессе между ranked_search/discover/extract.

Из извлечённого текста выбираются максимум два непрерывных фрагмента по 1200 символов. Строки оглавления с точечными лидерами исключаются. Модель возвращает ID фрагмента; Rust подставляет настоящий текст, проверяет его непрерывное присутствие в источнике и literal API/version/date ограничения. Склейка двух разных мест не становится цитатой. Отдельное поле extract `page_title` сохраняет HTML head title: название PostgreSQL не теряется при выборе основного текста страницы. Заголовок и текст остаются недоверенными данными.

Второй модельный вызов проверяет реальную помощь исходному вопросу, его обязательные аспекты, а также слабые свидетельства, вопросы и явно устаревшие документы. При ошибке или несогласии повышения нет. Всего максимум **4 попытки чтения документов, 3 модельных вызова, 180 секунд** после model preflight до 15 секунд. При начальной классификации более чем в одном batch чтение пропускается ради модельного бюджета.

Повышенный результат содержит `requirement_evidence`: реальные цитаты, ID, source_url, page_title, SHA-256 text_hash. `evidence` содержит первые 160 символов основной цитаты. Документный HTTP-статус возвращается только после фактического ответа; успешное извлечение помечено http_extract. Сохранены ошибки и partial. В MCP доступны прежние четыре инструмента; research и factual-answer фильтр не добавлены.

Исходный SERP prompt, literal/evidence gate и original20 не ослаблены. Их сохранность и совпадение runtime-кода с финальным прогоном проверены отдельно. После прогона удалён только датированный тестовый replay-harness; его исходник сохранён с диагностикой.

## Как проверяли

Первый [development8](../feasibility/recall-cases-v1.json) заморожен до поиска: HTTP, PostgreSQL, asyncio, CSS, csv, Git, Node.js и Promise. Одна из восьми исходных классификаций получила oMLX memory guard; она не превращена в нерелевантный результат. Для отладки повторно использовались сохранённые SERP/HTML.

Отвергнуты генеративный план требований с выдуманными обязательствами, цитирование целых оглавлений и чрезмерно строгая проверка почти полного ответа. Промежуточный вариант с точным копированием короткой цитаты вернул три полезные страницы на development8, но **не дал повышений на следующих шести вопросах**. Эти [шесть вопросов](../feasibility/recall-validation-cases-v1.json) стали development-набором после обнаружения потерь на пунктуации цитат и HTML-заголовках. Исходный файл и неуспешные результаты сохранены; holdout для итогового варианта они не являются.

Затем до окончательной реализации выбора ID фрагментов заморожен [финальный fresh8](../feasibility/recall-final-cases-v1.json). После просмотра его результатов правила не менялись. Baseline получен реальным Rust-валидатором из **того же первого модельного вызова, того же пула и тех же SERP**; текущий вариант добавляет только подтверждённые повышения. Повторной генерации baseline ради удачного результата нет.

## Итог fresh8

В пуле 142 карточки, 20 предварительно пригодных источников. Разметка объединяет SERP и успешно прочитанный текст выбранных страниц; полные тексты остальных страниц не проверены. Это **recall классификации в наблюдаемом пуле**, а не полный recall интернета или всех страниц. Чтение первых background-кандидатов создаёт смещение pooling в сторону уже высоко ранжированных страниц.

Возвращена [страница box-sizing](https://www.jakpsatweb.cz/css/box-sizing.html): в прочитанном тексте явно объяснены оба режима и учёт padding/border. Она поднялась с background на первое место. Все **1/1** новые direct проверены автором; дополнительных FP в этой серии не обнаружено. Два старых FP сохранились: широкий фрагмент CSS-главы и неоднозначное GitHub-обсуждение reset. Нулевой FP для всего инструмента не достигнут.

Пять SERP-only положительных суждений пограничны. Если понизить их, TP 4 → 5, FP 6 → 6, recall 26,7% → 33,3%. Направление изменения сохраняется, абсолютные precision/recall чувствительны к собственной разметке. Один новый положительный пример не устанавливает частоту ошибок на других темах.

## Стоимость и доступность

Fresh8: **16 операций поискового fetch, 32 попытки чтения документов, 23 модельных вызова**, 8/8 валидных исходных классификаций; ошибок модели в этом режиме не было. Полное время вопроса 29,6–63,9 секунды, медиана 50,4 секунды. Отдельный latency baseline без чтения не измерялся. Таймауты, HTTP 503, ошибки извлечения и DOM limit сохранены; блокировки не обходились.

Длинные отладочные серии неоднократно получили oMLX HTTP 400 prefill memory guard. Корневая причина накопленного memory pressure не локализована. После остановки своей серии проверялся ноль активных/ожидающих запросов и выгружалась только наша MiMo 9B через установленный локальный API. Финальные вопросы запускались по одному со свежей загрузкой модели. Сервис и глобальные настройки не изменялись. Это контролируемый режим измерения релевантности; устойчивость непрерывной сессии **не доказана**.

За весь текущий цикл, включая отрицательные варианты и release MCP smoke: 46 поисковых fetch-операций, 96 попыток чтения документов, 108 сохранённых модельных попыток, из них 6 отказов memory guard; отдельно один прерванный запрос без результата. Повторно использованные captures и готовый v03 не посчитаны дважды. Это операции загрузки, включая ошибки; редиректы могут добавлять HTTP-запросы на проводе. Разбивка находится в машинной сводке.

## Проверки и оставшиеся ограничения

Пройдены fmt, 32 обычных теста, Clippy all-targets с -D warnings, release build, три offline stdio-теста и именованный offline B17 export parity. Регрессии проверяют реальные ID цитат, запрет выдуманных/склеенных фрагментов, исключение точечного оглавления, учёт fetched head title, отказ второго проверяющего и общий документный circuit в MCP.

Release через настоящий MCP stdio повторил CSS-вопрос: 2 поисковых вызова, 4 чтения, 3 классификации; новая страница с цитатой/хешем вернулась первой. Ответ partial честно содержит две ошибки извлечения Naver и понижения недоказанных первоначальных direct. Private model_calls/settings в MCP-ответ не попадают.

Полные captures, вызовы, хеши, отказы и команды лежат в диагностической папке `runs/recall-2026-10-29/`; долговечные выводы и разметка — в doc/feasibility и Project Context. Original20 SHA-256: `b67e3269830ae0e976aa9b4c5dc2f6b9c3e922ad1adda35738289d6b1b8325d6`.

Основные оставшиеся потери: только четыре background-страницы, два коротких фрагмента, literal-ограничение может не попасть в выбранный фрагмент, а второй reviewer всё ещё иногда требует слишком полного свидетельства. Полезные страницы tempfile, Rust PoisonError, Go и Git прочитаны, но не повышены. Следующий технический кандидат — выбор фрагментов с обязательными API/date-якорями; он здесь не реализован и потребует нового отдельного набора.

Direct означает релевантность, не истинность. На development найден релевантный сторонний материал с неверным утверждением об откате TRUNCATE; официальная прочитанная документация ему противоречит. Factual-answer проверка остаётся отдельным этапом. Независимая приёмка, original20 day2, VPS, публичный Chromium и нагрузочная проверка не выполнялись; полный пилот по-прежнему не принят.

Project Context обновлён: research revision 9, состояние проекта, verification и last_result текущей задачи. Lint, свежесть index и context:check прошли. Doctor: WARN, 15 ok / 5 warn / 0 fail; отсутствие Git и связанные tooling-предупреждения сохраняются. Пустой heuristic refactor-review после ошибок Git не объявлен независимым ревью.
