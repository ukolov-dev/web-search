# Локальная сборка и MCP-прогон — 28.10.2026

**Результат:** release-бинарник Rust собран на Mac / Apple Silicon. Локальный MCP stdio работает с настоящим отдельным клиентом rmcp; доступны search и extract. Это проверка транспорта и операций чтения, а не приёмка полного пилота.

## Проверки сборки и протокола

Rust 1.95.0, зависимости закреплены в Cargo.lock. После загрузки rmcp 3.8.0 сборка выполнялась с `--release --locked --offline`; использован локальный `.cache/cargo`.

| Проверка | Результат |
| --- | --- |
| cargo fmt --check | Пройдена |
| cargo clippy --locked --offline --all-targets -- -D warnings | Пройдена |
| Unit-тесты | 8 passed, 1 ignored — отдельный браузерный runtime-тест |
| MCP-тесты против финального release-бинарника | 3 passed, 1 ignored — живой тест запускается отдельно |
| Отдельный живой MCP-тест | 1 passed, 5,60 с |
| Обнаружение инструментов | Ровно search и extract; схемы отклоняют дополнительные поля |
| Initialize с MCP 2025-11-25 | Версия согласована, tools capability объявлена |
| Отказ некорректным запросам | 16 случаев: пробельный/слишком длинный query, лимиты, неизвестный engine/инструмент, лишние поля, пустой/слишком большой массив URL, локальные/файловые адреса, userinfo |
| Жизненный цикл | После ошибки доступны дальнейшие вызовы; EOF завершает процесс без постороннего stdout |
| Занятость и отключённый источник | Отдельный unit-тест подтверждает busy/source_disabled без обращения к сети |

В проверках параметров принимается только явный MCP-отказ: JSON-RPC error либо tool result с isError=true. Таймаут и разрыв транспорта не считаются успешной валидацией.

## Живой прогон через stdio

Проверяемый запрос поиска: `Rust ownership borrowing documentation`, max_results=3.

| Операция | Фактический результат |
| --- | --- |
| extract: Rust Book, What is Ownership? | 24 995 Unicode code points, 107 блоков, truncated=false; 400 мс; SHA-256 совпал с текстом, полученным клиентом |
| extract: тот же пакет + несуществующая страница | status=partial: текст первой страницы сохранён, второй документ содержит HTTP 404 |
| extract: только несуществующая страница | status=error, isError=true; HTTP 404 сохранён как ошибка |
| Bing | HTTP 200, 821 мс, 3 результата; первые два URL ведут на соответствующие разделы Rust Book |
| DuckDuckGo | HTTP 202, 411 мс; isError=true, затем source_disabled при повторном вызове без нового сетевого запроса |

Обход блокировки DDG и автоматическое переключение на другой источник не выполнялись. Один удачный запрос Bing не отменяет ранее найденные нерелевантные ответы на другие запросы. Основной и резервный поисковые источники по-прежнему не квалифицированы.

После живого прогона исправлена только идентификация сервера в initialize: вместо имени/версии SDK возвращаются web-search/0.1.0. Финальный бинарник пересобран и повторно проверен тремя тестами stdio. Живой запрос к заблокированному источнику не повторялся. В машинном отчёте отдельно записаны хеш бинарника живого прогона и хеш финальной сборки.

- Бинарник: `target/release/web-search`.
- Пример подключения MCP-клиента: [examples/mcp-local.json](../examples/mcp-local.json); глобальная конфигурация агента не изменялась.
- Контракт и границы текущей реализации: [local-mcp.md](local-mcp.md).
- Сводка с контрольными суммами: [feasibility/mcp-results-2026-10-28.json](../feasibility/mcp-results-2026-10-28.json).
- Полный локальный ответ, включая извлечённый текст: `runs/mcp-2026-10-28/live.json` — исключён из Git.

```sh
./target/release/web-search mcp
```

В терминале процесс ожидает MCP JSON-RPC; его должен запустить клиент с stdin/stdout. Для search/extract модель и ключ не нужны.
